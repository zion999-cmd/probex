# P0001.12.3：AI Assistant & Action Gateway

**状态**：已完成
**日期**：2026-09-29  
**依赖**：P0001.12.2

## 目标

让 AI 从“只会解释 Probex”升级为“**能理解上下文、调用正式能力、执行受控操作、验证结果**”。

AI 不直接操作领域模块，更不能直接调用交易所 Adapter。

统一路径：

```text
AI Assistant
    ↓
Capability / Action Manifest
    ↓
Action Gateway
    ↓
Policy + Confirmation
    ↓
Existing Product / Runtime Owner
```

P0001.12.2 已经补齐 AI 所需的 fill、raw facts、account timeline、health、readiness authority 等只读事实基础。:chatgpt-content-reference{index="0"}

## 架构

```text
                    Probex Core
                   /           \
                  ▼             ▼
          Product Service   Action Gateway
             READ               ACT
                  \             /
                   ▼           ▼
                    Assistant
                       │
              ┌────────┼────────┐
              ▼        ▼        ▼
             UI       CLI     Agent API
```

Assistant 是五个 Surface 的全局能力，**不是第六个一级页面**。

## 设计

### 1. Assistant Context

AI 每次交互都获得结构化上下文，而不是靠用户重复描述：

```text
AssistantContext
├── surface
├── runtime_id
├── mode
├── environment
├── venue
├── symbol
├── selected_run_id
├── selected_decision_id
├── selected_order_id
├── selected_fill_id
├── replay_position
└── active_blockers
```

上下文只能引用 Product facts，不复制领域状态。

### 2. Action 分级

固定四级：

```text
L0 READ
L1 PRODUCT
L2 RUNTIME
L3 CAPITAL
```

#### L0 READ

AI 可自动执行：

```text
inspect
explain
compare runs
query evidence
query raw facts
query health
query blockers
```

#### L1 PRODUCT

只影响产品视图：

```text
navigate
select run/order/decision
filter
open evidence
replay play/pause/step/seek
generate report
export report
change visualization window
```

允许自动执行。

#### L2 RUNTIME

影响运行实例，但不直接表达交易意图：

```text
start replay
stop replay
start paper
stop paper
stop testnet runtime
request reconciliation
```

必须经过 `ActionGateway`。

对有明显副作用的动作要求确认。

#### L3 CAPITAL

第一版全部：

```text
unavailable_by_design
```

包括：

```text
place order
cancel order as manual trading action
buy/sell
change leverage
change position
change risk limits
force entry/exit
modify readiness authority
```

### 3. Action Manifest

增加机器可读契约：

```text
GET /api/v1/actions
```

每个 Action 至少描述：

```text
action_id
name
level
parameters
side_effect
confirmation_required
allowed_modes
result_schema
availability
unavailable_reason
```

Manifest 是 AI 能做什么的唯一正式来源。

AI 不允许自行“猜一个 API”。

### 4. Action Gateway

核心接口：

```text
ActionRequest
├── action_id
├── parameters
├── context
├── requested_by
└── confirmation
```

返回：

```text
ActionResult
├── action_id
├── status
├── started_at
├── ended_at
├── result
├── reason_code
└── resulting_fact_refs
```

状态建议：

```text
SUCCEEDED
REFUSED
FAILED
UNKNOWN
CONFIRMATION_REQUIRED
```

`UNKNOWN` 仍然不能伪装成 FAILED 或 SUCCESS。

### 5. Confirmation

不能所有操作都弹确认，也不能完全没有确认。

第一版：

```text
READ       → 不确认
PRODUCT    → 不确认
RUNTIME    → 按 action 定义
CAPITAL    → 不可用
```

例如：

```text
replay seek           自动
generate report       自动
stop PAPER            确认
stop TESTNET          确认
request reconciliation 可自动或轻确认
```

Confirmation 必须绑定具体：

```text
action_id
parameters
runtime_id
expires_at
```

旧确认不能用于新的动作。

### 6. Action Audit Trail

所有 L1/L2 动作都记录：

```text
who
what
when
context
parameters
result
reason
```

但不创建第二套交易 Event Store。

这是产品操作审计，不是订单事实 Owner。

### 7. Assistant UI

五个 Surface 右侧提供可折叠 Assistant Drawer。

例如用户当前选中一个 LOST order：

```text
Context
Order: xxx
Run: xxx
State: LOST

Assistant:
“为什么这个订单 LOST？”

Actions:
[打开 Evidence]
[跳到对应 Market 时间点]
[Replay ±30s]
[请求 reconciliation]
```

Action 按钮必须来自 Action Manifest。

### 8. Assistant 与 Surface 联动

AI 应能执行：

```text
“看一下刚才异常发生的位置”
→ Activity 定位事件
→ Market 跳到对应时间
→ 展开 evidence

“比较昨天两个 Testnet run”
→ Performance / Compare
→ 自动选择两个 run

“从异常前 30 秒重放”
→ Market / Replay
→ seek + play
```

重点是：

> AI 不只是回答文字，而是改变产品状态并执行正式 Action。

### 9. Agent / CLI 接口

CLI 增加：

```text
probex actions
probex action describe <id>
probex action invoke <id> ...
```

AI/Agent 与 UI 使用同一个 Action Gateway。

禁止单独做“AI 专用后门”。

## 边界

### 包含

- AssistantContext
- Action Manifest
- Action Gateway
- L0 READ
- L1 PRODUCT
- 部分 L2 RUNTIME
- confirmation contract
- action audit trail
- Assistant Drawer
- Surface navigation/action integration
- CLI / Agent action interface
- capability/action contract tests

### 不包含（关键）

- 不允许 AI 直接调用 Binance
- 不允许 AI import ExecutionEngine / RiskGate / MakerPolicy
- 不新增人工 Buy/Sell
- 不开放 place-order
- 不开放 leverage/risk 参数修改
- 不开放 force entry/exit
- 不开放 readiness authority 修改
- 不让 AI 绕过原 runtime Owner
- 不创建第二套交易控制路径
- 不引入自主交易 Agent
- 不让 LLM 决定 Risk policy
- 不实现 P0001.13 rate-limit/latency 后端

```text
assistant/

```

具体实现可调整，但 `ActionGateway` 必须保持独立边界。

## 成功标准

1. AI 能读取当前 Surface 和选中对象上下文。
2. AI 能解释 decision/order/fill/blocker。
3. AI 能导航 UI 到指定 run/order/time。
4. AI 能控制 Replay play/pause/seek。
5. AI 能生成/导出报告。
6. 至少一个真实 L2 Runtime Action 能通过 Gateway 执行。
7. 需要确认的动作无法绕过确认。
8. confirmation 不能跨 runtime/action 重放。
9. 每个 Action 都有审计记录。
10. Manifest 明确显示 CAPITAL 全部 unavailable。
11. UI / CLI / Agent 共用同一个 Action Gateway。
12. AI 无法直接触及 Binance Adapter。
13. UNKNOWN ActionResult 显式保留。
14. 不改变现有交易决策路径。
15. 全量测试不回归。

实施顺序建议很简单：

```text
先 commit + push P0001.12.2
→ 再实施 P0001.12.3
→ 不进入 P0001.13
```

这一步完成后，Probex 才真正具备“AI-native 产品”的第一版骨架。
