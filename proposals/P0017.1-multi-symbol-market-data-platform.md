## 0. 目标与非目标

### 0.1 目标
把 Probex 的行情能力从"一次运行、单标的、数据依附 run"升级为**与 run 解耦、可被多个运行与回测共享的多标的市场数据平台**：

1. **Universe 发现**：从交易所 `exchangeInfo` 发现真实可交易对（不硬编码），按状态/产品类型筛选，用户显式订阅，遵守订阅上限。
2. **多标的采集**：在现有连接器之上做多 symbol 合流订阅与**按 symbol 隔离**的状态/健康/时间戳/错误；单标的故障不污染其他标的。
3. **共享市场数据集**：按 `symbol + 时间 + 数据类型` 持久化，含来源/时间戳/质量/缺口；**独立于 run 生命周期**，可追溯、可复现、不可被后续数据悄悄改写。
4. **只读查询 + 产品 UI**：全标的列表、单标的详情与切换、数据质量/采集状态；失败显示真实错误，不伪造行情。

### 0.2 非目标（本阶段明确不做）
- ❌ 不改策略（MakerPolicy）、订单（OrderTracker）、会计（AccountingCore）、风控（RiskGate）规则；不加组合级风险（那是 P0017.2）。
- ❌ 不接账户、不做任何交易所写操作；不动现有 TESTNET 0.001 BTC 仓位。
- ❌ 不接第二家交易所（多标的 ≠ 多 venue；venue 仍只有 Binance 一个实现）。
- ❌ 不做多标的 PAPER 交易闭环、不做回测产品（P0017.2/.3）。
- ❌ 不用合成数据冒充真实行情；DEMO 合成路径保持显式隔离，不进入本数据集。
- ❌ 不无限订阅全市场（有上限/配额）。

## 2. 数据与状态契约

### 2.1 Universe 与订阅状态机
从 `GET /fapi/v1/exchangeInfo` 的 `symbols[]` 发现（复用并**泛化**现有解析器；当前 `parse_exchange_info(raw, symbol=...)` 只取单个，新增"列举全部"的纯函数，不改其单标的行为）。

- **发现状态**（每个 symbol 一条 immutable 描述）：
  - `DISCOVERED`：在 exchangeInfo 中且 `status="TRADING"`、`contractType` 属于本阶段支持的永续集合；
  - `UNAVAILABLE`：存在但不可订阅（非 TRADING / 被筛选规则排除 / 交易所标记）。
- **订阅运行态**（每个被选 symbol）：`IDLE → SUBSCRIBING → HEALTHY ⇄ STALE → RESUBSCRIBING/UNAVAILABLE`。
  - 与既有 `BookHealth`（AWAITING_SNAPSHOT/HEALTHY/STALE/RESYNCING）对应但**不替换**它：订阅态描述"这个 symbol 的采集通道"，BookHealth 仍描述单 symbol 盘口可信度。
  - 每个 symbol 独立：`source`、`last_exchange_ts`、`last_receive_ts`、`event_age_ms`、`book_health`、`error`、`gap/resync 计数`、持久化水位。
- **筛选规则**（只做只读、保守默认；参数化，不发明业务值）：
  - 仅永续（`contractType` 永续变体）、`status=TRADING`、`quoteAsset` 在允许集合（默认 `USDT`，可配置）、`symbol` 在可选 allowlist 或通过前缀过滤；
  - 具体默认 quote 集合 / 最小流动性门槛**先核实官方字段后在实施记录中给出**，无可靠字段则不加该门槛（不用猜）。

### 2.2 共享市场数据集（核心新契约）
- **组织键**：`dataset_root/<venue>/<symbol>/<kind>/<yyyy-mm-dd>/<partition>.jsonl`
  - `kind ∈ {book, trade, mark}`（与现有 EventType 对齐；首期可只落 `book` 快照序列 + `trade`，`mark` 同构）。
  - 每行 = 一条规范化记录（canonical JSON），含 `venue, symbol, kind, exchange_ts, receive_ts, source, schema_version, payload, quality?`。
  - **append-only + 内容寻址/序号**：复用 `JsonlEventWriter` 的"严格递增、损坏即拒绝、O_APPEND+fsync"纪律；写器按 `(venue,symbol,kind,day)` 分片。
- **不可变 / 可复现**：
  - 已落盘分区**只追加不改写**；迟到数据进入"迟到区/补偿标记"，不回改已定稿分区（与"不能用后续补齐悄悄改变回测结果"一致）。
  - 数据集有 **manifest**：每个分片记录行数、首尾 ts、字节数、内容 hash、schema 版本与来源；Run 将来只**引用** `(dataset 版本/区间/hash)`（本阶段先产出 manifest，run 侧引用留待 P0017.2/.3）。
- **与 run 解耦**：采集进程可在没有任何策略 run 时独立运行；run registry 不持有数据集所有权。
- **缺口追踪**：按 symbol 记录期望连续性（用现有 update-id / pu 判据）与缺口区间，查询时随数据返回 `gaps`，不插值、不伪造。

### 2.3 读取 / 查询契约（只读 API，新增，不破坏既有）
- `GET /api/v1/market/universe` → 发现到的标的列表 + 订阅态 + 发现时间/来源（分页有界）。
- `GET /api/v1/market/symbols/<symbol>/status` → 单 symbol 采集健康/水位/错误。
- `GET /api/v1/market/symbols/<symbol>/candles|trades?start=&end=&limit=` → **从共享数据集**读取（区别于现有"当前接线缓冲"的 candles）；无数据返回显式空/UNKNOWN，不返回合成值。
- 既有 `/api/v1/market/candles`（当前运行缓冲）**语义不变**，响应中继续标注 `source`。
- 所有新端点 GET-only；CAPITAL/写动作不变（`unavailable_by_design`）。

## 3. 采集架构（复用，不重写连接器）

**数据源范围决策（人类 2026-10-11）**：不引入 CCXT、不做通用多数据源/多 venue 抽象；多标的只在**现有 Binance `LiveMarketDataRuntime` 之上编排**（每标的一个 runtime 实例）。

- **每标的一个 `LiveMarketDataRuntime`**（复用其已验证的 REST snapshot 对齐 / pu 连续性 / resync / 重连 / 每标的 `FeatureEngine`），新增一个**编排层 MultiSymbolMarketCollector**：
  - 发现：启动/TTL 到点拉 `exchangeInfo`（复用 `parse_universe`）。
  - 订阅集：从 universe 中按显式选择 + `max_symbols` 上限确定（默认 16）。
  - 轮询：在采集线程上轮转调用每个 runtime 的 `pump_once`；按信封 stream 路由到对应标的（runtime 内部已完成，编排层只收集产出）。
  - 持久化：把每标的 states/trades/mark 写入对应 `MarketDatasetWriter`（按 symbol 隔离）。
  - 健康：每标的独立状态/时间戳/错误；单标的故障只影响该标的（独立 runtime ⇒ 天然隔离）。
- 连接预算：每 runtime 2 条 WS（public/market 两 tier）；16 标的 = 32 条，远低于 300/IP。**合流多标的到更少连接的优化本期不做**（YAGNI；受 `max_symbols` 约束）。
- 单标的路径（现有 `--market-source binance-public`）与多标的采集**并列保留、互不回归**。
- 采集以 `MarketSourceAdapter` 同形态对产品层暴露事实（多标的版按 symbol 取状态）。

- 新增一种**只读数据平台运行形态**（建议 `--market-source binance-public --universe ...` 的扩展或独立 `marketdata` 子命令；最终形态在实施记录确定并保持与 `scripts/probex.sh` 一致）：

- UI（在既有 5 Surface 内扩展，不新增第六个一级导航）：
  - **Market**：全标的列表（状态/最新价或 mark/年龄/健康徽标）、点击进入单标的详情（K线/盘口/成交/质量/缺口，数据来自共享数据集或该 symbol 实时缓冲）、标的切换。

  - 无数据/STALE/UNAVAILABLE：显式 UNKNOWN/STALE + 原因；451/发现失败显示真实错误，不生成占位列表。
- 继续遵守"UI 只经 Product Read Model"；不直连连接器。

## 7. 成功标准（离线验收与真实验收分开）

> 验收结论（2026-10-11，人类选择 (b)：离线完成、真实 E2E 待网络）：**A = PASS、B = NOT RUN（HTTP 451）、C = PASS**。本提案**不标记为全部完成**。

**A. 离线（脚本化传输 + 真实报文形态；CI 可跑，无网络）— PASS**
1. 用多 symbol 的 exchangeInfo 样例，发现器正确列出 TRADING 永续、排除非 TRADING/非允许 quote，且**不硬编码**列表。
2. 合流信封按 stream 路由到正确 symbol 的 FeatureEngine；A symbol 的畸形报文/缺口**不改变** B symbol 状态与数据。
3. 每个 symbol 的状态/时间戳/错误独立；无数据 ⇒ UNKNOWN/STALE，不伪造。
4. 数据集写入：按 symbol/kind/day 分片、append-only、损坏 fail-closed、manifest hash 正确；重开续写不重复/不覆盖；迟到数据不改写已定稿分片。
5. 只读查询端点从数据集返回正确区间；越界/无数据显式空 + reason；分页有界。
6. 现有单标的全套测试与架构守卫全绿（不回归）；UI 模块守卫/契约测试覆盖新组件。

**B. 真实 E2E（需非受限网络出口；451 时 NOT RUN，禁止用模拟替代）— NOT RUN（HTTP 451，外部阻塞）**
7. 在可访问 Binance 的出口下：发现器返回真实可交易对；订阅 ≥2 个 symbol，均进入 HEALTHY 并持续更新；数据集落盘可重启后续读；杀掉一个 symbol 的流不影响另一个。
8. 浏览器验证全标的列表/切换/详情来自真实源，断开时显示真实 STALE/错误。
9. 记录实测订阅上限/频率/存储占用到 LIMITS_FINDINGS；真实结果与保守默认一致或据此调整并复诉。

**C. 边界 — PASS**
10. 不新增任何订单/写路径；`api.write` 仍 unavailable；核心 Owner 与 CAPITAL 守卫通过；TESTNET 写次数 = 0、仓位不变。
11. Proposal/roadmap/current_state/handoff/status 与事实一致；detached clean checkout 全绿。

> "测试通过"不构成 B 类验收；B 必须有真实源证据，受阻则明确 `NOT RUN（451/出口）`。
