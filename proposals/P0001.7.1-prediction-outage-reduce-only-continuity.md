## 0. 本阶段固定契约（供审查）

| 项目 | 规则 |
| --- | --- |
| prediction 不可用（缺失 / 过期 / 缺 horizon） | **仅**禁止新增**增加暴露**的报价；`allow_new_increasing = False` |
| 同上，reduce-only 报价 | **允许新增**（`allow_new_reducing = True`）—— 降低 exposure 不得被预测可用性阻断 |
| prediction 的用途 | 不可用时**完全退出方向性调整**（`fresh_prediction()` 返回 `None`）：不做 adverse-selection 后退/禁止、不做预测方向后退，**不伪造 prediction** |
| reduce-only 报价仍必须通过 | 市场可用性（`tradeable` / book health / best bid+ask+mid 存在）、`KillSwitch`、订单合法性、`post-only`、`RiskGate`（最终权威，含 `REDUCE_ONLY_WOULD_INCREASE` 兜底） |
| 定价依据（无 prediction） | 只依据 best bid/ask、tick、库存偏置、post-only；cost floor 仅约束**增加暴露**的报价（reduce-only 天然豁免） |
| 规模依据（无 prediction） | 有界 `confidence_factor` 取下界（`derived_confidence = 0`），不放大风险 |
| 生命周期 | prediction valid → stale：增加暴露的旧报价 **CANCEL**；合法 reduce-only 报价 **KEEP 或 REPLACE**（走正常比价/比量/年龄逻辑），**不是全部撤掉** |
| 其他全局门保持不变 | `MARKET_UNHEALTHY`、`UNKNOWN_EXPOSURE`、`HALT_ALL` 仍然阻断**全部**新增报价（含 reduce-only）；`REDUCE_ONLY` 熔断允许新增 reduce-only |
| 不修改 | Prediction Runtime、Execution 状态机、Risk 限额；不引入 taker emergency exit |

## 1. 实施结果（2026-09-28）

**改动**

- `strategy/maker/policy.py`
  - `evaluate_global_gate()`：`PREDICTION_STALE` 分支改为 `allow_new_reducing=True`（新增注释说明「prediction 不是降险的必要条件」）。
  - 新增 `fresh_prediction(prediction, config, now_ms)`：过期/缺失/缺 horizon → `None`；`decide()` 用它替换 `_side_plans` 的 prediction 入参，
    因此 prediction 不可用时定价与规模**完全不做方向性调整**，且不会沿用过期分布。
  - `_blocked_gate()` docstring 明确：默认阻断全部新增报价，例外为 `PREDICTION_STALE` 与 `REDUCE_ONLY`。
- `strategy/maker/__init__.py`：导出 `fresh_prediction`。
- 测试
  - 新增 `tests/fault/test_prediction_outage_reduce_only.py`（16 条：SC-1 – SC-7 + 确定性 + 过期 prediction 不参与方向）。
  - `tests/fault/test_stale_prediction_quote_cancel.py`：新增 `test_sc5_reduce_only_quote_is_never_canceled_by_a_stale_prediction`、
    `test_sc4_increasing_resting_quote_is_canceled_on_stale_prediction`；原「stale 时 reduce-only 必须 KEEP」的断言改为
    「可 KEEP 或 REPLACE，但不得 CANCEL/NONE」（这是本提案授权的 SC-5 语义修正，不是削弱验收）。
  - `tests/integration/test_maker_paper_execution.py`：`test_reduce_only_exit_quote_survives_a_prediction_outage`
    取代原断言（原断言要求旧 reduce-only 挂单保持 `OPEN`，与 SC-5 允许 REPLACE 不符）：中断后**必须仍有**一个 reduce-only 出口报价，
    且**不得再有**增加暴露的报价；REPLACE 走 P0001.6 的 cancel-before-replace（两轮驱动）。

**刻意保留 / 未改动（如实记录）**

1. `UNKNOWN_EXPOSURE`（P0001.6.1：资料不足订单数量 > 0）在策略层仍阻断**全部**新增报价（含 reduce-only）。
   本提案的「包含」范围只覆盖 prediction 中断，故未扩大改动；但 `RiskGate` 本身只拦增加暴露的订单，
   二者存在不一致 → 已作为观察项记录（见 P0001.7 提案 §1 Observation），待人类裁决。
2. 有**新鲜** prediction 时，`adverse_selection_block` 仍会禁止该侧（含 reduce-only 侧）新增报价 —— 这是 P0001.7 SC-4 的既有
   已验收语义，本提案未改动；同类不一致性亦记录为观察项。

## 2. 原提案文本（原样保留）

目标
确保 Prediction 缺失、过期或 Provider 暂时不可用时：
禁止增加 exposure
但允许安全的 reduce-only Maker quote

避免预测服务故障导致已有仓位无法被动减仓。
设计
全局 gate 从：
prediction invalid
→ 禁止所有新 quote

改为：
prediction invalid
├─ increasing exposure → 禁止
└─ genuine reduce-only → 可继续评估

reduce-only 仍必须通过：
Market health
Book health
Mark freshness
KillSwitch
Order validity
RiskGate
post-only

Prediction 只是不再成为降低风险报价的必要条件。
定价
无 Prediction 时 reduce-only 不做方向预测调整。
只依据：
best bid / ask
tick
inventory
post-only
basic lifecycle

生成保守 Maker 报价。
不要伪造 prediction。
生命周期
如果 prediction 从 valid → stale：
增加 exposure 的已有 quote
→ CANCEL

reduce-only quote
→ 可 KEEP / REPLACE

不是全部撤掉。
边界
包含
- prediction outage 下 reduce-only continuity
- stale/missing prediction 的方向区分
- existing quote lifecycle 修正
- deterministic/fault tests
不包含
- 不做 taker emergency exit
- 不绕过 RiskGate
- 不修改 Prediction Runtime
- 不修改 Execution 状态机
- 不做新的风险限额
- 不进入 Fill Simulation
成功标准
1. 有 long 仓位 + 无 prediction，可以生成 sell reduce_only。
2. 有 short 仓位 + 无 prediction，可以生成 buy reduce_only。
3. 同条件下任何增加 exposure 的 quote 都禁止。
4. prediction 过期时，增加 exposure 的旧报价被 CANCEL。
5. prediction 过期时，合法 reduce-only 报价可 KEEP/REPLACE。
6. market unhealthy / stale mark / HALT_ALL 仍能阻断。
7. RiskGate 仍是最终权威。
8. 原 997 条测试继续通过。
