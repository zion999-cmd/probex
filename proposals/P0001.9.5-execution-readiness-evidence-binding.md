### 0.2 关键契约

1. **正式路径不再接受裸 `market_ready=True`**：`LiveReadinessEvidence.market` 必须是 typed `MarketReadinessEvidence`；
   harness 侧的映射**委托**产品模块（单一来源）。
2. **主网验收不再由裸 bool 表达**：`EnvironmentValidationEvidence` 需 `VALIDATED` + `validated_at` + `validation_id` +
   `account_scope` + `evidence_source` 才被认作 validated；testnet 记录永远不等于主网（SC-3 / SC-23）。
3. **HWM 只能来自 tracker**：`ReadinessEvidenceCollector.from_high_watermark_tracker(tracker, ...)`；
   每次 collect 取**当前**证据（因此 HWM 变化会改变 digest 并让旧授权失效）。
4. **recovery generation**：`RecoveryGeneration(discontinuity_count, invalidation_count)`
   分别来自 `PrivateAccountRuntime.discontinuity_events` 与 `StartupRecovery.reason_log`（复用既有机制，不新造状态机）。
5. **market generation**：market epoch 在 invalidate/resync/重连时推进（§12 方案 A）。
6. **授权只有 LIVE_READY 且 scope 匹配环境时才能签发**；`authority_ttl_ms` 必须显式给出（无默认业务值）。
7. **授权不含任何执行能力**（SC-18），**不绕过**逐订单 `RiskGate`（SC-19）。

# 原提案文本（原样保留）

## 目标

把当前 `LiveReadinessGate` 的“纯判定能力”升级为未来 Execution 可依赖的**受控授权链**。

当前这些输入仍可由调用方直接提供：

```text
market_ready: bool
mainnet_private_validated: bool
HighWatermarkEvidence
boundary_present: bool
```

P0001.9.5 不改变这些底层事实模型，而是在其上建立：

```text
受控 runtime/state
      ↓
Evidence Collector
      ↓
LiveReadinessGate
      ↓
ExecutionReadinessAuthority
```

未来真实 ExecutionAdapter **只能消费 authority，不能消费裸 `LIVE_READY` bool/result**。

---

## 背景

Testnet 已真实验证：

```text
recovery = RECOVERED
market = READY
private latency = KNOWN
daily pnl = KNOWN
drawdown = KNOWN
readiness = TESTNET_LIVE_READY
```

风险事实链已经闭合。

现在剩余缺口是**provenance（来源）和 lifetime（生命周期）**：

1. `market_ready` 还是 bool；
2. `mainnet_private_validated` 还是 bool；
3. HWM evidence 可以由调用方直接传入；
4. `LiveReadinessResult` 是某个时刻的结论，但没有执行授权 TTL；
5. runtime 在 READY 后断线时，旧的绿色 result 本身不会自动失效。

第五点尤其关键：

```text
18:00 LIVE_READY
18:00:01 private stream disconnect
18:00:02 使用旧 result 下单
```

这是 P0001.9.5 必须堵住的窗口。

## 设计

### 1. 保留 `LiveReadinessGate` 为纯函数

现有：

```text
LiveReadinessEvidence
→ LiveReadinessGate
→ LiveReadinessResult
```

继续保留。

不要把 runtime、REST、store I/O 塞进 Gate。

P0001.9.5 新增的是**上游 collector + 下游 authority**。

---

### 2. 新增受控 Evidence Collector

建议：

```text
ReadinessEvidenceCollector
```

它负责从真实 Owner 读取：

```text
recovery
  ← StartupRecovery.current result

private stream
  ← PrivateAccountRuntime telemetry
  ← runtime.snapshot_boundary

account
  ← latest AccountSnapshotObservation

historical risk
  ← current RiskSnapshot

high watermark
  ← HighWatermarkTracker.evidence()

market
  ← product-side MarketReadinessEvidence

environment
  ← EnvironmentValidationEvidence

risk policy
  ← explicit human configuration
```

调用方不再逐字段拼装生产级 `LiveReadinessEvidence`。

---

### 3. `market_ready: bool` 改为 typed evidence 来源

当前测试 harness 已经证明真实 market readiness 可以由：

```text
book health
snapshot anchor
depth gap/resync
malformed count
mark freshness
feed freshness
aggTrade observations
```

推导。

本阶段把这套**事实映射**提升到产品侧最小模块，例如：

```text
MarketReadinessEvidence
- ready
- observed_at
- book_health
- anchored
- mark_age_ms
- feed_age_ms
- depth_gap_count
- resync_count
- malformed_count
```

Collector 消费该 evidence。

`LiveReadinessGate` 最终仍可判断：

```text
market.ready
```

但正式路径不再接受外部：

```python
market_ready=True
```

### 不要

把整个 `tests/live/market_readiness.py` 原样搬进产品代码。

只提升**契约与纯事实映射**。

---

### 4. Mainnet validation 不能再是 bool

当前：

```text
EnvironmentEvidence(
    environment=MAINNET,
    mainnet_private_validated=True
)
```

理论上任何调用方都能声明。

改成：

```text
EnvironmentValidationEvidence
- environment
- validation_status
- validated_at
- validation_id
- account_scope
- evidence_source
```

至少状态：

```text
NOT_VALIDATED
VALIDATED
STALE
```

Mainnet：

```text
MAINNET_LIVE_READY
```

必须依赖：

```text
environment == MAINNET
AND validation_status == VALIDATED
AND validation evidence 与当前部署匹配
```

### 关键

P0001.9.5 **不执行 Mainnet 验收**。

因此当前 Mainnet 仍应：

```text
BLOCKED: MAINNET_PRIVATE_NOT_VALIDATED
```

---

### 5. HWM 必须从 Tracker 获得

正式 collector：

```text
HighWatermarkTracker
→ tracker.evidence()
```

禁止产品 orchestration 自己写：

```text
HighWatermarkEvidence(
    status=ACTIVE,
    peak_equity=...
)
```

单元测试当然可以直接构造。

这是架构约束，不是假装 Python 提供密码学防伪。

---

### 6. Recovery 必须绑定当前 generation

仅有：

```text
RecoveryStatus.RECOVERED
```

还不够。

需要引入或暴露一个**recovery generation / recovery epoch**：

```text
recovery_generation
```

每次：

```text
disconnect
listenKey recreate
continuity loss
recovery invalidation
```

generation 必须变化。

Authority 记录生成时的：

```text
recovery_generation
```

未来执行前如果 generation 不一致：

```text
authority invalid
```

这样旧的 READY 不能跨断线继续使用。

---

### 7. Authority 是短时 capability，不是永久状态

新增：

```text
ExecutionReadinessAuthority
```

建议字段：

```text
authority_id
issued_at_ms
expires_at_ms

scope
environment

recovery_generation
market_evidence_ts
account_snapshot_ts
clock_calibration_ts

hwm_activation_id
hwm_generation

risk_policy_fingerprint
evidence_digest

readiness_result
```

其中：

```text
readiness_result.status
必须 == LIVE_READY
```

否则不得生成 authority。

---

### 8. Authority TTL 必须显式配置

不能：

```text
今天 LIVE_READY
明天继续拿这个 authority 下单
```

增加：

```text
authority_ttl_ms
```

由人类配置，不设默认业务值。

验证：

```text
now_ms <= expires_at_ms
```

超时：

```text
AUTHORITY_EXPIRED
```

需要重新收集 evidence + Gate evaluate。

---

### 9. Evidence digest

Collector 对本轮用于判断的关键 evidence 生成 canonical digest，例如：

```text
environment
recovery generation
private continuity/boundary
clock calibration
account captured_at
market evidence timestamp/state
historical known flags
HWM activation/generation/peak
risk policy
```

形成：

```text
evidence_digest
```

目的不是密码学防攻击，而是：

> 让日志明确回答“这张执行授权是基于哪组事实生成的”。

---

### 10. Authority validator

新增纯判定：

```text
ExecutionReadinessAuthorityValidator
```

至少检查：

```text
not expired
scope matches requested environment
recovery generation unchanged
HWM generation unchanged
HWM activation_id unchanged
current kill switch still NORMAL
```

对于会快速变化的 runtime 事实，不要求全部重新 hash 比较；TTL + generation/invalidation 负责生命周期。

---

### 11. Runtime discontinuity 必须即时让旧 authority 失效

Private runtime 已有：

```text
subscribe_discontinuity(...)
```

P0001.9.5 应利用已有机制。

发生：

```text
disconnect
reconnect
listenKey recreate
stop
```

必须确保：

```text
Recovery invalidates
→ generation changes
→ old authority cannot validate
```

**不要新造第二套 disconnect 状态机。**

---

### 12. Market discontinuity 同样不能沿用旧 authority

如果：

```text
BookHealth != HEALTHY
depth gap
market invalidated
```

旧 authority 不应继续授权新增风险。

有两种方式都可接受：

```text
A. market generation
```

或最小方案：

```text
B. future execution 每次仍走实时 RiskGate，
   authority TTL 很短；
   market hard failure 同时使 execution orchestration invalidate authority
```

我更建议 **A：market readiness generation**，与 Recovery generation 对称：

```text
MarketEvidence.generation
```

market invalidate / resync epoch 改变即失效。

---

### 13. RiskGate 仍然必须每单执行

关系必须固定：

```text
ExecutionReadinessAuthority
        ↓
“这个 runtime 有资格进入 execution”
        ↓
OrderProposal
        ↓
fresh RiskSnapshot
        ↓
RiskGate
        ↓
ALLOW / REJECT
```

因此：

```text
valid authority
≠ order allowed
```

以及：

```text
RiskGate ALLOW
≠ execution authority valid
```

两个门不能合并。

---

### 14. Testnet/Mainnet scope 强隔离

```text
TESTNET_LIVE_READY authority
```

只能：

```text
scope = TESTNET
```

未来 Mainnet adapter 必须拒绝。

绝不允许：

```text
TESTNET authority
→ Binance Mainnet adapter
```

---

### 15. Authority 不负责下单

本 Proposal 到此结束。

最终只产生：

```text
ExecutionReadinessAuthority
```

不存在：

```text
submit_order()
cancel_order()
BinanceExecutionAdapter
```

## 成功标准

1. 正式 collector 不再接受裸 `market_ready=True`。
2. product-side market evidence 必须由真实 market/runtime facts 推导。
3. Mainnet validation 不再由裸 bool 表达。
4. 正式路径的 HWM evidence 只能从当前 `HighWatermarkTracker` 获取。
5. `LIVE_READY` 才能生成 `ExecutionReadinessAuthority`。
6. BLOCKED 绝不能生成 authority。
7. Authority 明确包含 Testnet/Mainnet scope。
8. Testnet authority 无法用于 Mainnet。
9. Authority 有明确 TTL；过期后拒绝。
10. private discontinuity 后旧 authority 立即失效。
11. recovery generation 改变后旧 authority 失效。
12. market health epoch/generation 改变后旧 authority 失效。
13. HWM rebase/generation 改变后旧 authority 失效。
14. kill switch 从 NORMAL 改变后旧 authority 不再有效。
15. evidence digest 对同组 canonical evidence 稳定。
16. evidence 改变后 digest 改变。
17. Authority 能追溯到 recovery/market/HWM/risk-policy 版本。
18. `ExecutionReadinessAuthority` 不包含任何 submit/cancel 能力。
19. RiskGate 仍然逐订单执行，authority 不绕过它。
20. Testnet 真实全链能够：
    ```text
    collect
    → evaluate
    → issue TESTNET authority
    → validate
    ```
21. 制造 private discontinuity 后，同一个 authority 验证失败。
22. market invalidate 后，同一个 authority 验证失败。
23. Mainnet 因没有真实 validation record 继续 BLOCKED。
24. 产品代码仍无 Binance submit/cancel endpoint。
25. 全量测试 + detached worktree PASS。
