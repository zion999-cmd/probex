## 0. 事实契约（来自 TypeSafe 官方文档 + 实测）

来源：`docs.typesafe.ai/api`、`docs.typesafe.ai/primitives/choice`、`docs.typesafe.ai/primitives/noul`
（旧集成 `activation-room-poc/src/gate/jev-gate.ts` 与 D-018 的 P2 实测相互印证）。

**请求**：`POST https://openrouter.ai/api/v1/systemone`，`Authorization: Bearer $OPENROUTER_API_KEY`，`Content-Type: application/json`

```jsonc
{ "model": "jev-1.13",           // alias；实际 resolved model 由响应给出，不硬编码
  "state": <object>,             // 待评估内容
  "questions": { "<qid>": { "type": "choice"|"noul"|"score", "instructions": ..., "criteria": ... } } }
```

- `noul` 问题：`criteria` **可选** `{ "true": <desc>, "false": <desc> }`
- `choice` 问题：`criteria` **必填**，是 `{ "<option>": <desc|null> }` 的 map（最多 255 项）
- question id 不会发给模型

**响应**：

```jsonc
{ "id": "gen-dec-...", "model": "typesafe/jev-1.13-<date>", "provider": "TypeSafe",
  "answers": { "<qid>": { "type": "noul", "noul": 0.99 } |                      // Noul：无 confidence
                         { "type": "choice", "choice": "<opt>", "probabilities": {...}, "confidence": 0..1 } },
  "usage": { "input_tokens": int, "output_tokens": int, "cost": float } }
```

- `probabilities` 覆盖全部选项且**求和为 1**；`choice` 是概率最高的选项；`confidence` 由分布导出
- Noul **没有** `confidence`（协议本身如此，不得伪造）
- 错误语义：`401` 凭据无效、`422` 请求体校验失败、`429` 限流、`529` 过载（后两者按文档应退避重试）

## 1. 实现契约

### 1.1 Included（本阶段实施）

- `SystemOneTransport`：真实 HTTP（标准库 `urllib.request`）、Bearer、timeout、envelope 提取、HTTP 错误映射、调用 telemetry
- `SystemOneProvider`：`PredictionProvider` 实现，负责 wire ⇄ domain 适配
- Choice / Noul 请求构造（4 Choice `market_5s|15s|30s|60s` + 4 Noul `buy_adverse_selection|sell_adverse_selection|buy_fill|sell_fill`）
- typed answers 严格解析 → 映射为 `jev-market-v1` domain answers，再由**既有** `parse_jev_prediction` 生成 `Prediction`
- `PredictionRecord` 追加证据字段（requested model / resolved model / provider / response id / usage / latency）
- HTTP 错误映射到既有 failure type（4xx → `TRANSPORT_ERROR`；408/425/429/5xx（含 529）→ `PROVIDER_ERROR`；timeout → `TIMEOUT`）
- 真实 integration test（opt-in）+ 小规模真实 latency 记录
- 正式废弃 Chat Completions 热路径入口（SC-10），保留实验记录

### 1.2 NOT Included（未触碰）

- 不使用 `typesafe/jev-router`、不使用 Chat Completions、不做 prompt engineering、不解析自然语言、不做 markdown JSON 提取
- 不用 Score 表示 adverse-selection probability
- 不修改 `MarketState`、不修改 Scheduler、不改 `jev-market-v1`（domain 语义未变，仅 wire 适配）
- 不实现 Strategy / Accounting / Risk；不 fallback 到通用 LLM

### 1.3 固定实现细节（供审查）

| 项目 | 取值 |
| --- | --- |
| endpoint | `https://openrouter.ai/api/v1/systemone`（base + path，均可覆盖但默认固定） |
| model | 请求别名 `jev-1.13`；`resolved_model` 取自响应并写入记录 |
| 五分类映射 | `market_<h>` 的 **Choice** `criteria` = 5 个 bucket（`strong_down/down/flat/up/strong_up`），响应 `probabilities` 直接映射为 `FutureReturnDistribution` |
| adverse selection | **Noul**：`buy_adverse_selection` = P(passive buy 成交后 5s 内 mid 下跌超过 X bps)；`sell_adverse_selection` = P(mid 上涨超过 X bps) |
| X（阈值 bps） | **必填构造参数**，提案未定义具体数值 → 不由实现自造；生产值需人类/设计给定（测试用显式测试值） |
| fill probability | **Noul**：`buy_fill` / `sell_fill` |
| `provider_confidence` | 取**最近 horizon**（`market_5s`）Choice 的 `confidence`；缺失则该字段为 `None`（不伪造） |
| `derived_confidence` | 仍由 `future_return` 分布派生（既有定义不变） |
| Noul 的 confidence | 永不使用、永不伪造（协议里不存在） |
| `raw_response` | 记录的是**供 strict parser 消费的 domain answers JSON**；wire 原始字节保存在 transport telemetry（与 P0001.4.1 一致） |
| 未知字段 | 响应外层与 answers 内的未知字段一律忽略，不进入 domain JSON（SC-6） |
| `state` | 取 domain payload（`jev-market-v1` 全量，含版本与 `market_state_hash`）去掉 `questions` |
| 记录字段 | `PredictionRecord` 追加 `requested_model` / `resolved_model` / `response_id` / `usage`（均有默认值，向后兼容）；`model` 保持=请求 model |

| Choice 答案 | `{"type":"choice","choice":"up|flat","confidence":0.32–0.44,"probabilities":{…}}`，样本内五分类求和 = 1.000000 |
| Noul 答案 | `{"type":"noul","noul":0.12–0.28}`，**无 confidence** |

对照 P0001.4.1：同一平台的 Chat Completions 路径为 4.9–19 s 且契约不稳定；typed 路径为 ~0.41–0.46 s 且契约稳定 →
**热路径切换的收益得到实测支持**。

**滞在的开项（不影响本阶段验收，但需人类/设计决定）**

1. **adverse-selection 阈值 X（bps）是必填参数，提案未给数值**。实现按要求把它做成必填构造参数，测试用 5.0 bps 仅为测试参数；
   生产值需要人类/设计给出（这是业务参数，不由实现编造）。
2. **五分类 bucket 目前是定性描述**（无 bps 分档）。这与 `jev-market-v1` 既有语义一致（该 schema 从未定义数值分档），
   但真实 Jev 也提示过「阈值未提供，分布是启发式估计」；若要校准，需要一次 schema 决策。
3. fill 概率的 horizon 固定为 5 s（与 adverse-selection 一致），属实现固定选择，已在 D-019 记录。
4. 观测到**一次瞬态失败**（多轮快速调用时，疑似限流/过载）。运行时的 backoff 已覆盖该场景；live 套件只在瞬态失败时有限重试，
   契约类失败（`INVALID_RESPONSE` / `PARSE_ERROR`）永不重试。
