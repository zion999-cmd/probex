P0001.10.2：UI + Reports
状态：已完成
日期：2026-09-29
依赖：P0001.10.1 Product Read Model + API
目标
为 Probex 提供工程/研究控制台和运行报告层。
本阶段只消费 .10.1 已定义的 Product API / Read Model，不直接读取领域内部对象，不重新实现交易逻辑。
核心目标：
看状态
看原因
看过程
看结果

背景
.10.1 负责：
Domain Owners
→ Product Read Model
→ Stable API

.10.2 负责：
Stable API
→ UI
→ Reports

UI 和 Reports 都只是消费者。
架构
Probex Core
    ↓
Product Service / API
    ↓
┌───────────────┬───────────────┐
│               │
Web UI        Report Builder
│               │
Human View    JSON / Markdown

不得：
UI → Binance connector
UI → RiskGate internals
UI → Accounting internals

设计
1. UI 定位
第一版是：
Engineering / Research Console

不是交易所终端，不追求 TradingView 风格。
页面建议固定为：
Overview
Market
Prediction
Strategy
Risk
Orders
Portfolio
Readiness
Evidence
Runs / Reports

2. Overview
必须一眼看到：
runtime mode
environment
symbol
market health
prediction freshness
latest maker decision
risk state
readiness state
active orders
position
equity
PnL
last update

UNKNOWN 必须明确显示为 UNKNOWN，不能显示 0。
3. Evidence / Decision Trace
这是 UI 最重要的部分之一。
用户必须能追溯：
MarketState
→ Prediction
→ MakerDecision
→ RiskDecision
→ Order
→ ExecutionEvent
→ Fill

并能回答：
为什么没有下单？
为什么撤单？
为什么 Risk 拒绝？
为什么 readiness blocked？

第一版只做结构化 trace，不做复杂因果图。
4. Reports
新增 RunSummary。
建议包含：
runtime identity
start/end time
duration
market health stats
prediction count/freshness
decision counts
risk reject counts
orders submitted
accepted/rejected/unknown
fills
fees
realized pnl
unrealized pnl
max exposure
final position
readiness blockers
anomalies

Report 输出至少支持：
JSON
Markdown

HTML 可以后加，不是本阶段必须。
5. Run Identity
报告必须绑定唯一 run identity：
runtime_id
mode
environment
symbol
started_at
config fingerprints
data range

不能只输出一个孤立 PnL。
6. UI 刷新模型
第一版可以轮询：
GET /api/v1/snapshot

不要求 WebSocket 实时推送。
原因很简单：
先稳定产品契约，再优化实时体验。

边界
包含
- Web engineering console
- Overview
- Market / Prediction / Strategy / Risk / Orders / Portfolio / Readiness 页面
- Evidence trace
- RunSummary
- JSON / Markdown report
- REPLAY / PAPER / TESTNET 共用 UI schema
- UNKNOWN 明确展示
- UI/API contract tests
- report determinism tests
不包含（关键）
- 不直接调用领域模块
- 不直接调用 Binance connector
- 不直接下单
- 不做 Buy / Sell 按钮
- 不做手工改仓位
- 不做 leverage 控制
- 不做 risk 参数编辑
- 不修改 MakerPolicy
- 不修改 RiskGate
- 不修改 Accounting
- 不新增策略
- 不做 Mainnet UI
- 不做用户登录系统
- 不做多租户
- 不做复杂权限
- 不做移动端
- 不做 TradingView 替代
- 不做复杂图表系统
- 不做策略优化器
- 不做 Freqtrade / Hummingbot / lob-engine 接入
- 不把 Reports 变成第二套 accounting
目录结构
建议：
ui/
    app/
    pages/
        overview/
        market/
        prediction/
        strategy/
        risk/
        orders/
        portfolio/
        readiness/
        evidence/
        runs/
    client/

reports/
    types.py
    builder.py
    markdown.py
    json.py

tests/
    unit/
        test_report_builder.py
        test_report_determinism.py
    integration/
        test_ui_api_contract.py

具体前端技术栈让实现 Agent 根据现有环境决定，不在 Proposal 里锁死。
成功标准
1. UI 只通过 .10.1 Product API 获取事实。
2. REPLAY / PAPER / TESTNET 使用同一页面结构。
3. UNKNOWN 不显示为 0 / empty / healthy。
4. Risk reject 能看到正式 reason code。
5. Readiness blocker 能完整展示。
6. MakerDecision 能追溯 prediction identity。
7. Active order 能追溯对应 decision。
8. Report 可稳定输出 JSON + Markdown。
9. 同一 Run 数据生成的报告内容确定性一致。
10. Report 不重新计算 Accounting。
11. UI 不存在直接交易写入口。
12. 全量现有测试不回归。

## 实施记录（2026-09-29）

授权：人类本会话明确指令（「10.2,10.3 你读取, 实施」），按 CLAUDE.md §7.1 记录。
依赖说明：本提案所依赖的 `.10.1 Product Read Model + API` 已由 `P0001.10` 交付（`product/` + `api/`）。

### 落地内容

| 目录 | 文件 | 职责 |
| --- | --- | --- |
| `reports/` | `types.py` | `RunIdentity`（run_id / runtime / started_at / ended_at / config fingerprints / data range）+ `RunSummary`（含 max exposure、unrealized pnl、final position 等） |
| | `builder.py` | 由**已记录事实**汇总（计数/求和）；fills / fees / pnl / exposure / position 一律由调用方传入，**不重算 Accounting** |
| | `json.py` | 确定性 JSON（`sort_keys=True`，拒绝 NaN） |
| | `markdown.py` | 确定性 Markdown（字段顺序固定，UNKNOWN 显示为 `UNKNOWN (reason)`） |
| | `run_summary.py` | 兼容入口（re-export） |
| `ui/` | `app/index.html` + `app/console.css` | console 外壳（无 build step，纯静态） |
| | `client/api.js` | **唯一数据入口**：只访问 `/api/v1/*`（SC-1） |
| | `client/render.js` | 共享渲染原语：UNKNOWN 显式（SC-3） |
| | `client/console.js` | 路由 + 轮询 `/api/v1/snapshot`（`POLL_INTERVAL_MS = 2000`） |
| | `pages/{overview,market,prediction,strategy,risk,orders,portfolio,readiness,evidence,runs}/page.js` | 十个页面，**同一结构跨 REPLAY/PAPER/TESTNET**（页面内不含模式分支，SC-2） |
| `api/` | `routes/reports.py` + `server.py` | 只读 `GET /api/v1/reports/run-summary`（`?format=markdown`）；静态 `/ui/*` 服务（含路径穿越防护） |
| `tests/` | `unit/test_report_builder.py`、`unit/test_report_determinism.py`、`integration/test_ui_api_contract.py` | 25 条新测试（含 UI 契约与确定性） |

### 成功标准映射

| SC | 证据 |
| --- | --- |
| 1 UI 只用 Product API | `test_ui_only_talks_to_the_product_api`（扫描 `ui/**/*.js`：非 `/api/v1/`、非 `/ui/` 的 URL 一律失败；且不得出现 `binance` / `connectors`） |
| 2 三种模式共用页面结构 | 十个页面存在且都不含 `REPLAY`/`TESTNET` 分支（`test_every_page_exists_and_has_the_same_structure`） |
| 3 UNKNOWN 不显示为 0 | `client/render.js` 的共享 `fact()` 原语（`test_unknown_rendering_helper_is_shared`）+ Markdown `UNKNOWN (reason)`（`test_markdown_shows_unknown_with_reason`） |
| 4 Risk reject reason code | `risk` 页与 `/api/v1/risk` 的 `rejects`（.10.1 已保证 reason code 原样） |
| 5 Readiness blocker 完整展示 | `readiness` 页：`reasons` + `details` 全量渲染 |
| 6 MakerDecision → prediction identity | `evidence` 页的 trace（`identity` 列） |
| 7 Active order → decision | `orders` 页的 `decision` 列（`decision_id`） |
| 8 JSON + Markdown | `summary_to_json` / `summary_to_markdown`（`test_json_and_markdown_are_both_available`）+ HTTP `?format=markdown` |
| 9 报告确定性 | `test_report_determinism.py`（同一事实 ⇒ 字节一致；fingerprint 顺序无关；事实变化 ⇒ 输出变化） |
| 10 不重算 Accounting | 全部会计事实由调用方传入（`test_accounting_facts_are_passed_through_not_recomputed`） |
| 11 UI 无交易写入口 | UI 只 GET `/api/v1/*`；任何写尝试在 API 侧 404/405（.10.1 断言） |
| 12 不回归 | **1844 passed / 0 failed / 24 skipped** |
