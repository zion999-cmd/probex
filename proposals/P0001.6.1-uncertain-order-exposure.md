## 0. 本阶段的固定契约（供审查）

原则：**不知道订单是否存在时，Risk 必须假设它仍可能存在。**

| 项目 | 取值 / 规则 |
| --- | --- |
| `confirmed_open_exposure` | ACTIVE 订单（PENDING_CREATE / OPEN / PARTIALLY_FILLED / PENDING_CANCEL）未成交部分 × 订单价格 |
| `uncertain_exposure` | **LOST** 订单未成交部分 × 订单价格（LOST 不是终态，必须继续占用风险额度） |
| `total_pending_exposure` | `confirmed + uncertain`；`OrderTracker.open_order_exposure()` 保留为该值的兼容别名 |
| `RiskSnapshot.open_order_exposure` | `confirmed + uncertain`（= 提案要求的 `total_pending_exposure`） |
| 新增快照字段 | `confirmed_open_exposure` / `uncertain_exposure` / `unresolved_order_count`（供审计与 gate 判定） |
| 资料不足 → fail closed | 外部事实不足以量化某个订单时（例如 adopt 需要 quantity/side/price 而缺失）：**不再「按 0 处理」**，而是在 tracker 记录为 *unresolved*；`unresolved_order_count > 0` 时 RiskGate **拒绝任何增加暴露的订单**（`UNCERTAIN_EXPOSURE_UNKNOWN`），但**放行 reduce-only 降暴露**（降风险是安全的） |
| 释放条件 | 只有 reconciliation **明确确认** CANCELED / FILLED / EXPIRED（或成功 adopt 补齐资料）才释放；仅「外部不再列出」不会释放 LOST 的额度 |
| 部分成交 | reconciliation 校正成交量后按**剩余量**重算（LOST → PARTIALLY_FILLED 时进入 confirmed） |
| 不修改 | Order 状态机、Accounting、late-fill 语义、`Order` 不变量均不动 |
| 快照入参一致性 | `build_risk_snapshot(open_order_exposure=..., confirmed_open_exposure=..., uncertain_exposure=...)` 若三者不自洽 → `ValueError`（fail closed，防止调用方给出矛盾的暴露） |

## 1. Included / NOT Included

- **Included**：LOST 计入风险暴露；confirmed / uncertain 分离；reconciliation 后释放；RiskSnapshot 暴露更新；
  restart / lost-order 测试；资料不足 fail closed。
- **NOT Included**：不修改 Order 状态机；不修改 Accounting；不接 Binance；不做真实 user stream；不实现持久化；
  不进入 Maker；不改变 late-fill 语义。

## 2.1 实施结果（2026-09-28）

- `risk/gate.py`：新增 increasing-only 检查 `_check_uncertain_exposure`（`unresolved_order_count > 0` → 拒绝新增暴露；
  reduce-only 降暴露仍放行）；`RiskLimits.enabled_checks()` 增加 `uncertain_exposure`。
- 测试：`tests/fault/test_uncertain_exposure.py`（15 条，SC-1 – SC-5 + 快照一致性）、

**关键行为自检**

| 场景 | 结果 |
| --- | --- |
| OPEN → LOST | `total_pending_exposure` 保持 100.0（confirmed 0 / uncertain 100），不下降 |
| LOST 期间新增买单（limit 120） | REJECT `OPEN_ORDER_EXPOSURE_LIMIT`（第二单从未发出） |
| LOST 期间 reduce-only 降暴露 | ALLOW |

| 快照入参不自洽（total ≠ confirmed + uncertain） | `ValueError`（fail closed） |

## 3. 原 P0001.6.1 提案文本（原样保留）

修正 LOST / 状态未知订单的风险暴露语义。
原则：
不知道订单是否存在时，Risk 必须假设它仍可能存在。

设计
OrderTracker 的 exposure 分成：
confirmed_open_exposure
uncertain_exposure
total_pending_exposure

其中：
ACTIVE
→ confirmed_open_exposure

LOST
→ uncertain_exposure

RiskSnapshot 使用：
open_order_exposure =
confirmed_open_exposure
+
uncertain_exposure

对于 LOST 订单，按剩余未成交数量 × 原订单价格计算风险暴露。
如果价格不存在或订单信息不完整：
fail closed

不能按 0。
当 reconciliation 明确确认：
CANCELED / FILLED / EXPIRED

才释放这部分 uncertain exposure。
边界
包含
- LOST 计入风险暴露
- confirmed / uncertain exposure 分离
- reconciliation 后释放
- RiskSnapshot 暴露更新
- restart / lost-order 测试
不包含
- 不修改 Order 状态机
- 不修改 Accounting
- 不接 Binance
- 不做真实 user stream
- 不实现持久化
- 不进入 Maker
- 不改变 late-fill 语义
成功标准
1. OPEN → LOST 后 total_pending_exposure 不下降。
2. LOST 期间第二个新增风险订单仍可能被 OPEN_ORDER_EXPOSURE_LIMIT 拒绝。
3. reconciliation 确认 CANCELED 后才释放 exposure。
4. reconciliation 确认部分成交时，exposure 按剩余量重算。
5. LOST 订单资料不足时 fail closed。
6. 原 867 条测试全部继续通过，并新增针对上述路径的 fault tests。
