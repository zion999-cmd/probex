P0001.9.7.1：Private Latency Cold-Start Bootstrap
状态：已完成
日期：2026-09-29
依赖：P0001.9.7
目标
允许干净、安静的账户首次启动，同时保持 UNKNOWN != healthy 和 fail-closed 原则。
核心不是绕过 latency gate，而是增加一种明确状态：
UNOBSERVED

它表示“当前没有业务事件，因此尚无样本”，不能和真正的 UNKNOWN/INVALID 混为一谈。
设计
Private latency 状态改为：
UNOBSERVED   # 尚未出现任何可测 private business event
HEALTHY      # 已有样本且满足阈值
UNHEALTHY    # 已有样本但超阈值
UNKNOWN      # 测量链异常/证据不可判定

首次冷启动只有满足全部条件时，允许签发 BOOTSTRAP authority：
Recovery == RECOVERED
Market ready
Private WS connected / continuity valid
Account flat
Probex open orders == 0
Foreign open orders == 0
Uncertain exposure == 0
Private latency == UNOBSERVED

BOOTSTRAP authority 必须比正常 authority 更窄：
scope       = TESTNET + symbol
TTL         = 很短
max_orders  = 1
post_only   = true
notional    <= 100 USDT
position cap 保持现有值

首笔订单触发真实 private event 后：
→ 得到 corrected private latency
→ BOOTSTRAP authority 立即失效
→ 重新 collect readiness
→ latency HEALTHY 才签发正常 ExecutionReadinessAuthority

如果首个事件得到：
UNHEALTHY / UNKNOWN

则立即 BLOCKED，不允许第二笔新增风险。
边界
包含
- 新增 UNOBSERVED 语义。
- 明确 cold-start bootstrap authority。
- 首个真实 private event 后强制升级到正常 readiness。
- Testnet 验证该闭环。
不包含（关键）
- 不允许 harness 私自发探测单。
- 不把 PRIVATE_LATENCY_UNKNOWN 普遍视为通过。
- 不允许 bootstrap authority 连续下多笔单。
- 不修改 MakerPolicy。
- 不修改 sizing 参数。
- 不修改 RiskGate 风险阈值。
- 不允许 Mainnet。
- 不接受“账户必须已有历史活动”作为产品限制。
成功标准
1. 完全 flat、0 order 的 Testnet 账户可从冷启动进入 BOOTSTRAP。
2. readiness 前没有旁路 submit。
3. BOOTSTRAP 最多允许第一笔合法 PostOnly order。
4. 第一笔 private event 产生真实 corrected-latency 样本。
5. BOOTSTRAP authority 随即失效。
6. latency HEALTHY 后才能获得正常 authority。
7. latency UNHEALTHY/UNKNOWN 时 fail closed。
8. 完成后再继续原 P0001.9.7 的 ≥30 分钟 Phase B。

**观察（§31，未改产品代码）**

1. 策略提案价是 float，序列化后可能超出 tickSize 精度（`83958.20000000001` 被交易所按精度拒绝）；adapter 依 D-048 **不自动 round** 是正确的，因此**调用方/序列化层需要 Decimal 量化**（harness 已自行量化）。
2. 短 TTL 与"等待自然 PLACE"存在时间竞争：authority 必须在**临近写入时刻**签发（harness 已改为写入前重新 collect + 重新签发，TTL 仍为短）。
3. 长预热窗口内的 WS 重连会正确地把 recovery 置为 BLOCKED ⇒ readiness 拒绝；harness 需要稳定的 ACTIVE+continuity 窗口才能继续（本次多次因重连而 fail closed）。

### JIT 签发契约（人类裁决，已实现）

- **禁止**"提前签发 authority 后长时间等待 PLACE"；正确顺序（同一轮）：
  等自然合法 PLACE → 重新 collect readiness → 断言 `RECOVERED` / `listening ACTIVE` / continuity / market ready /
  `latency == UNOBSERVED` → `issue BOOTSTRAP` → fresh RiskSnapshot/RiskGate → **立即**写。
- 机制化落地：
  - `BootstrapAuthorityCoordinator.activate` **保留**已消耗的 write attempt 额度，并在额度用尽后**拒绝**再次签发
    （否则可循环 re-issue 拿到无限次写入）；重新签发会递增 `bootstrap_generation` 并废止旧 authority。
  - `BootstrapWriteGate.check/authorize(..., private_continuity_valid)` 为**必填**参数：
    `None` / `False` ⇒ `PRIVATE_CONTINUITY_INVALID`（collect 与写请求之间 WS reconnect ⇒ 旧 readiness/authority 作废）。
  - adapter / orchestrator 在 BOOTSTRAP 分支传入 `context.private_continuity_valid`；NORMAL 分支不变（无回归）。
- 新增单测 6 条：过期即拒（零网络调用、零额度）/ 同轮重新 collect+issue 可通过 / 额度用尽后 re-issue 被拒 /
  collect 与写之间 continuity 失效被拒 / recovery generation 变化被拒 / orchestrator 在 continuity 失效后禁止新增暴露。
  全量 **1778 passed / 0 failed / 24 skipped**。

### 独立产品问题（本轮**未**解决，仅登记）

**Order price normalization ownership 未定义**：策略提案价以 float 表示，序列化后可能超出交易所 `tickSize` 精度
（实测 `83958.20000000001` 被交易所按 precision 拒绝）。adapter 依 D-048 **不自动 round** 是正确的，
但"谁负责 tick 量化"在契约中未定义。本轮 cold-start 验证中 harness 用 Decimal 量化到 tickSize，
**仅为测试输入适配**，不构成该产品问题已解决的任何声明。建议在后续 Proposal 中明确 ownership
（候选：strategy pricing 输出即 tick-exact；或执行层前置于适配器的 normalization 步骤）。
