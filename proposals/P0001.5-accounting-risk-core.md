## 0. 本阶段的固定契约（供审查）

原提案给出结构与边界，以下细节由实现固定并在 `context/decisions.md` 记录：

| 项目 | 取值 / 规则 |
| --- | --- |
| Fill 事实源 | `FillLedger` append-only；`(venue, symbol, fill_id)` 与 `(venue, symbol, trade_id)` 双键去重，重复仅返回 outcome、不重复记账 |
| Position 语义 | single symbol / net position / USDT-M perp；`qty>0` long、`qty<0` short、`qty=0` flat；不做 hedge mode |
| 反手 | 拆成 close leg + open leg：close 部分按旧均价实现盈亏，open 部分以成交价作为新均价；**不混合平均价** |
| `Position.realized_pnl` | **只含交易盈亏（不含手续费）** —— 这是 §7「fee / funding / realized trade pnl 分开统计」与 §5「mark 不得影响 realized」唯一自洽的读法；`net_realized = realized_trade_pnl − trading_fees + funding` |
| Fee | 累计为 `trading_fees`；`fee_asset` 必须等于结算资产（默认 USDT），否则拒绝该 Fill（**不做多币种换算**，NOT Included） |
| Funding | 独立账本 `FundingLedger`；正数=入账、负数=支付；影响 balance / equity / net_realized，**不是** Fill / Fee / realized trade pnl |
| Balance / Equity | `balance = initial_balance + realized_trade_pnl − trading_fees + funding`（由账本派生，不运行式累加）；`equity = balance + Σ unrealized` |
| Mark price | 显式注入 `update_mark_price(symbol, price, timestamp)`，**不使用 last trade** |
| 未知 ≠ 0 | 缺失 mark 时 `unrealized_pnl / notional / equity / drawdown` 为 `None`；Position 归零时 unrealized **恒为 0.0** |
| `notional` | `|qty| × mark`（无 mark 时为 `None`）；`gross_exposure = Σ|notional|`，`net_exposure = |Σ signed notional|` |
| Drawdown | `peak_equity` 在每次状态变更后刷新；`drawdown = peak_equity − equity`（绝对），`drawdown_pct = drawdown / peak_equity` |
| Daily loss | `realized_pnl_since(day_start_ts)`；`day_start_ts` 与 `now_ms` 均由**调用方注入**（提供 `utc_day_start_ms` helper）；risk / portfolio 不 import `time` |
| `available_balance` | `balance − open_order_exposure` |
| Risk 输入 | `RiskGate.evaluate(proposal, snapshot, *, book_healthy=True)`；只消费 immutable `RiskSnapshot`，不读 mutable accounting |
| Exposure 分类 | INCREASING（含反手）/ REDUCING / NEUTRAL；`reduce_only` 且实际会增大 exposure → REJECT |
| Reduce-only | 只受硬检查约束（订单参数合法性 / 数据完整性 / kill switch），**不受** position / notional / open-order / daily-loss / drawdown / leverage / liquidation 限额约束 |
| Kill switch（第一版） | 拒绝一切（含 reduce-only）；emergency policy 按 §11 留待后续定义 |
| 限额缺省 | 所有限额 `None` = 未启用；**已配置但数据缺失**（如无 mark、无 LiquidationInfo）→ REJECT（fail closed） |
| 无 leverage 配置 | 可用余额检查按 `effective_leverage = max_leverage or 1.0` 处理（保守：不允许杠杆） |
| 输出 | `RiskDecision(decision=ALLOW|REJECT, reason_code, details)`，绝不返回裸 bool |

**验证方式**：`REPLAY_SCRIPT` 重放 3 次逐字段一致；同序列**双重交付**（每笔 Fill 交付两次）得到完全相同的最终状态与快照（dedup 生效）。

**门控行为自检**

| 场景 | 结果 |
| --- | --- |
| 满仓 + 继续加仓 | REJECT `POSITION_LIMIT` |
| 满仓 + `reduce_only` 平掉一半 | **ALLOW**（不受限额约束，§11） |
| `reduce_only` 但会增大暴露（含反手） | REJECT `REDUCE_ONLY_WOULD_INCREASE` |
| kill switch（含 reduce-only） | REJECT `KILL_SWITCH` |
| book 不健康 / 无 mark / mark 过期 | REJECT `BOOK_UNHEALTHY` / `MISSING_MARK_PRICE` / `STALE_MARK` |
| 当日净亏损（含 fee + funding）达限 | REJECT `DAILY_LOSS_LIMIT` |
| drawdown 达限 | REJECT `DRAWDOWN_LIMIT` |
| 杠杆超限 | REJECT `LEVERAGE_LIMIT` |
| 强平距离过小 | REJECT `LIQUIDATION_DISTANCE`（强平价只来自 account adapter） |
| 已配置限额但数据缺失 | REJECT（`MISSING_DAILY_PNL` / `MISSING_LIQUIDATION_INFO` / `MISSING_MARK_PRICE`） |

**有意为之的行为（供审查）**

1. **空仓且无 mark 时不能下单**（`MISSING_MARK_PRICE`）：无法评估名义风险 → fail closed。
2. `balance` 由账本派生（`initial + realized − fees + funding`），不做运行式累加；`peak_equity` 在每次状态变更后刷新。
3. kill switch 第一版拒绝一切（含 reduce-only），emergency policy 按 §11 留待后续定义。
4. 非结算资产的费用/资金费一律拒绝（不做多币种换算）。

## 3. 原 P0001.5 提案文本（原样保留）

P0001.5：Accounting + Risk Core
状态：已提议
日期：2026-09-28
依赖：P0001.1–P0001.4.2
目标
建立与 Strategy / Exchange 解耦的账户账本与风险控制核心。
这一阶段不下单，解决两个问题：
发生了 Fill 以后，我到底持有什么？
在允许发订单之前，什么必须被拒绝？

核心原则：
Fill 是账户事实源；Risk 是所有未来 OrderIntent 的强制闸门。

架构
Fill / Funding / Mark
        │
        ▼
   Accounting Core
        │
        ├─ Position
        ├─ Balance
        ├─ Realized PnL
        ├─ Unrealized PnL
        ├─ Equity
        └─ Exposure
              │
              ▼
          RiskSnapshot

OrderProposal
      │
      ▼
   RiskGate
      │
 ┌────┴────┐
 ▼         ▼
ALLOW     REJECT

本阶段只实现这两层，不接 Execution。
设计
1. Fill Ledger 是唯一成交事实源
定义不可变：
Fill
- fill_id
- order_id
- venue
- symbol
- side
- price
- quantity
- fee
- fee_asset
- trade_id
- exchange_ts
- receive_ts

要求：
同一个 trade_id / fill_id
只能记账一次

Position、PnL、Balance 都从 Fill 派生。
不允许：
Position 直接被 Strategy 修改

2. Position 模型
第一版明确只支持：
single symbol
net position
USDT-margined perpetual

Position 至少包含：
qty
avg_entry_price
realized_pnl
unrealized_pnl
mark_price
notional

方向语义：
qty > 0 → long
qty < 0 → short
qty = 0 → flat

先不要做 hedge mode 双向仓位。
3. 平均成本与实现盈亏
必须覆盖：
加仓
部分减仓
完全平仓
反手

例如：
long 2 @100
sell 1 @110

则：
remaining qty = 1
avg entry = 100
realized pnl = +10 - fees

如果：
long 1 @100
sell 2 @110

则：
旧 long 1 平掉
+
新 short 1 @110

反手必须拆成：
close leg
open leg

不能直接重算一个混合平均价。
4. Balance ≠ Equity
正式定义：
Balance
= cash / settled account value

UnrealizedPnL
= open position marked to mark price

Equity
= Balance + UnrealizedPnL

不能像简单回测那样只维护余额。
5. 永续合约的 Mark Price
本阶段接受显式：
MarkPriceEvent

或测试注入：
update_mark_price()

不能用 last trade 代替 mark price。
原因：
PnL / liquidation / risk

应该基于交易所定义的 mark 体系，而不是成交价最后一笔。
6. Funding 单独入账
定义：
FundingPayment

至少：
symbol
amount
asset
timestamp
rate(optional)

Funding：
不是 Fill
不是 Fee
不是 realized trade pnl

但会影响：
Balance
Equity
Net PnL

三者必须分开统计。
7. Fee 独立累计
需要至少分：
trading_fee
funding
realized_trade_pnl

最终：
net_realized
=
realized_trade_pnl
- trading_fees
+ funding

不要只留一个“净盈亏”数字。
8. RiskSnapshot
Risk 不直接到处读取 mutable accounting 对象。
定义 immutable：
RiskSnapshot

包含：
balance
equity

position_qty
position_notional

gross_exposure
net_exposure

open_order_exposure
available_balance

realized_pnl_today
unrealized_pnl
drawdown

mark_price

以后 RiskGate 只消费 Snapshot。
9. OrderProposal
本阶段只定义 Risk 输入契约：
OrderProposal
- symbol
- side
- quantity
- price
- reduce_only
- post_only

它不是 Order。
没有：
exchange_order_id
status
fills

这些属于 P0001.6。
10. RiskGate
第一版支持：
Market data gate
Position limit
Notional limit
Open-order exposure
Available balance
Daily loss limit
Drawdown limit
Leverage limit
Liquidation-distance guard
Kill switch

输出不是 bool，而是：
RiskDecision

ALLOW / REJECT

reason_code
details

例如：
POSITION_LIMIT
NOTIONAL_LIMIT
DAILY_LOSS_LIMIT
STALE_MARK
BOOK_UNHEALTHY
KILL_SWITCH

这样以后 telemetry 可以统计到底是谁挡掉了订单。
11. Reduce-only 的风险语义
这是很重要的一条：
降低风险的订单不能和增加风险的订单完全一样检查。
例如当前：
long 0.003

position limit 已经满了。
一个：
sell reduce_only 0.001

不应该因为“position limit 已满”而被拒绝。
所以 RiskGate 必须区分：
increasing exposure
reducing exposure

但 reduce-only 也不能绕过：
数据异常
订单数量非法
kill switch 的 emergency policy

具体 emergency 语义后面定义。
12. Daily Loss / Drawdown
两者分开：
Daily realized/net loss

和：
Peak equity drawdown

不是一个指标。
Drawdown：
peak_equity
→ current_equity

Daily Loss：
day_start / realized result

时间边界必须通过 Clock 注入，不能直接 datetime.now()。
13. Liquidation Distance
第一版不自己实现 Binance 完整强平公式。
只定义：
LiquidationInfo
- liquidation_price
- mark_price
- distance_bps

由未来 Binance account adapter 提供真实值。
Risk 只做：
distance_bps < threshold
→ reject increasing exposure

避免现在错误复刻交易所复杂 margin tier 公式。
边界
包含
- immutable Fill
- Fill deduplication
- net Position
- avg entry
- partial close
- reversal
- realized PnL
- unrealized PnL
- fees
- funding
- balance
- equity
- mark price
- RiskSnapshot
- OrderProposal contract
- RiskGate
- position/notional/exposure limits
- daily loss
- drawdown
- leverage guard
- liquidation-distance guard
- kill switch
- deterministic replay/accounting tests
不包含（关键）
- 不实现真实 Order
- 不实现 exchange order lifecycle
- 不发 Binance API
- 不实现 cancel / replace
- 不做 partial-fill tracking state machine
- 不实现 hedge mode
- 不实现 cross-margin / isolated-margin 完整公式
- 不自己推导 Binance liquidation price
- 不实现 Strategy
- 不把 Jev Prediction 直接映射成订单
- 不实现 Maker pricing
- 不实现 UI
- 不持久化到账户数据库
- 不实现多币种资产换算
目录结构
建议：
portfolio/
  fills.py
  position.py
  accounting.py
  funding.py
  types.py

risk/
  types.py
  snapshot.py
  gate.py
  limits.py

测试：
tests/unit/
  test_fill_ledger.py
  test_position.py
  test_accounting.py
  test_funding.py
  test_risk_snapshot.py
  test_risk_gate.py

tests/integration/
  test_accounting_risk.py

tests/replay/
  test_accounting_determinism.py

tests/fault/
  test_fill_duplicates.py
  test_risk_fail_closed.py

成功标准
1. 同一组 Fill 重放两次，Position / PnL / Balance / Equity 完全一致。
2. duplicate fill / trade id 不得重复记账。
3. 加仓、部分平仓、完全平仓、反手都有明确测试。
4. Fee / Funding / Realized Trade PnL 分开记录。
5. Mark Price 改变只能影响 Unrealized PnL / Equity，不能改变 Realized PnL。
6. Position 归零后 unrealized PnL = 0。
7. reduce_only 降低 exposure 时不会因为 position/notional limit 已满被误拒绝。
8. increasing exposure 超过 position/notional/open-order exposure 任一限制时必须 REJECT。
9. daily loss / drawdown / kill switch 命中时，新增 exposure 必须关闭。
10. liquidation distance 过小时拒绝新增 exposure，但不自行计算 liquidation price。
11. Accounting 与 Risk 都不 import Prediction/Jev/Strategy/Execution。
12. Replay 不依赖 wall-clock。
13. 现有 612 条离线测试继续通过。
