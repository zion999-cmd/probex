### 0.2 关键不变量

1. **单轮顺序固定**（§2）：先 drain 外部事件 → 更新 Tracker/Accounting → **再**取 fresh RiskSnapshot → 收集 market/prediction → decide → 执行 → 再 drain → 记录；**绝不**"先下单再刷新风险快照"。
2. **position 是派生事实**：默认从 `AccountingCore` 取当前持仓；显式传入时必须与快照一致，否则 `OrchestratorError`（fail closed）。
3. **existing_orders 只来自 Tracker**（§5）：`OrderManager.active_orders`。
4. **每侧最多一个 active**（§4）：违反 ⇒ `ORDER_MULTIPLICITY_VIOLATION` ⇒ 停止新增 + 触发 reconciliation；**不擅自取舍**。
5. **authority 只在新增暴露前校验**（§8）：失效 ⇒ 不 submit（note `authority_invalid:<REASON>`）；**cancel 仍执行**。
6. **REPLACE = cancel-before-replace**（§3）：旧单未确认终态前**绝不**补挂。
7. **UNKNOWN 不重试**：submit/cancel 的 UNKNOWN 交由 `query_order` / user stream / reconciliation 收敛（D-048 延续）。
8. **observe-only**：`execution_enabled=False` ⇒ 所有写动作被记录并跳过（loop 保持稳定，不抛异常）。
9. **stop ≠ 平仓**（§17）：撤 Probex 挂单 → drain → 报告残留；持仓残留只报 `POSITION_REMAINS`。
10. **risk budget 由调用方注入**（`risk_budget_provider`）：orchestrator **不做风险数学**；未知 ⇒ 策略 fail closed。

# 原提案文本（原样保留）

## 目标

把现有几条已经独立验证的链真正串成一个 **Testnet Live Loop**：

```text
Market Runtime
→ Prediction Runtime
→ MakerPolicy
→ fresh RiskSnapshot / RiskGate
→ ExecutionReadinessAuthority
→ BinanceExecutionAdapter
→ OrderTracker / Accounting
```

本阶段验证的是：

> 策略决策能否在持续运行中安全地转化为真实 Testnet 订单生命周期。

不做 Mainnet，不重新设计 MakerPolicy，不新增新的交易策略。

---

## 背景

现在各层都已经具备：

```text
Market Data        ✓
Jev Runtime        ✓
MakerPolicy        ✓
RiskGate           ✓
Recovery           ✓
Historical Risk    ✓
High-Watermark     ✓
Readiness Authority✓
Binance Adapter    ✓
```

但它们还没有一个正式产品侧 owner 把：

```text
PLACE
KEEP
CANCEL
REPLACE
```

稳定地执行起来。

因此本阶段的核心不是“增加能力”，而是：

```text
wiring + lifecycle ownership + failure behavior
```

---

## 架构

```text
Binance Market Runtime
        ↓
   MarketState
        ↓
Prediction Runtime
        ↓
 PredictionRecord
        ↓
 Accounting / Tracker
        ↓
 fresh RiskSnapshot
        ↓
    MakerPolicy
        ↓
   MakerDecision
 PLACE / KEEP / CANCEL / REPLACE
        ↓
 LiveExecutionOrchestrator
        ↓
 authority validation
        ↓
 ExecutionEngine / OrderManager
        ↓
 BinanceExecutionAdapter
        ↓
 Binance Testnet
        ↓
 user stream
        ↓
 adapter.poll()
        ↓
 Tracker / Accounting
```

---

## 设计

### 1. 新增唯一编排 Owner

新增：

```text
LiveExecutionOrchestrator
```

职责仅限：

- 收集本轮输入；
- 调 MakerPolicy；
- 将 QuoteAction 映射到已有 ExecutionEngine / OrderManager；
- 驱动 poll / event bridge；
- 处理 authority 失效；
- 输出 telemetry。

它不自己：

```text
算价格
算 size
算 risk
生成 prediction
解释 Jev
```

---

## 2. 单轮执行顺序固定

每轮严格：

```text
1. ingest / poll external events
2. update Tracker / Accounting
3. build fresh RiskSnapshot
4. collect latest MarketState
5. collect latest PredictionRecord
6. MakerPolicy.decide(...)
7. 对每侧执行 action
8. 再 poll 一次 execution events
9. 记录本轮结果
```

顺序不能变成：

```text
先下单
→ 再刷新 risk snapshot
```

---

## 3. QuoteAction 映射

### PLACE

```text
QuoteDecision.proposal
→ ExecutionEngine.submit(...)
```

要求：

```text
proposal != None
```

最终仍经过：

```text
fresh RiskSnapshot
→ RiskGate
→ authority
→ adapter
```

---

### KEEP

什么都不做。

不能为了“刷新状态”偷偷 replace。

---

### CANCEL

调用：

```text
ExecutionEngine.cancel(...)
```

撤单不需要 LIVE_READY，这个既有原则保持。

---

### REPLACE

必须沿用既有：

```text
cancel-before-replace
```

流程：

```text
old order
→ cancel
→ confirmed terminal
→ only then submit replacement
```

不能在同一 tick 里假设 cancel 成功然后直接新挂。

---

## 4. 每侧只允许一个 active quote

当前 MakerPolicy 本身就是单侧单 quote 语义。

所以 orchestrator 必须保持：

```text
最多：
1 active BUY
1 active SELL
```

如果发现：

```text
同侧 >1 active order
```

视为：

```text
ORDER_MULTIPLICITY_VIOLATION
```

进入 fail closed：

```text
停止新增
→ reconciliation
```

不能擅自选择一个保留、一个忽略。

---

## 5. existing_orders 必须来自 Tracker

MakerPolicy 的：

```text
existing_orders
```

只能取：

```text
OrderManager.active_orders
```

不能从：

```text
REST openOrders
```

直接喂策略。

REST / external facts 只用于 reconciliation。

本地 Tracker 仍是生命周期 Owner。

---

## 6. ExternalFactsProvider 正式实现

P0001.9.6 只有 Protocol。

本阶段补正式 wiring：

```text
PrivateExternalFactsProvider
```

实现：

```text
parse_open_orders()
parse_recent_fills()
```

底层复用既有：

```text
PrivateRestClient.open_orders()
PrivateRestClient.user_trades()
orders parser
trades parser
```

原则：

```text
read failure → unavailable
true empty   → ()
```

继续保持：

```text
UNKNOWN ≠ EMPTY
```

---

## 7. Reconciliation 触发条件

正常情况下不每 tick 做完整 reconciliation。

只在这些情况触发：

```text
submit UNKNOWN
cancel UNKNOWN
LOST order
private discontinuity
skipped transition > 0
external facts conflict
startup
```

流程：

```text
pause new exposure
→ fetch external facts
→ reconcile
→ RecoveryGate
→重新取得 authority
```

未收敛前：

```text
禁止新增 exposure
```

---

## 8. Authority 生命周期

orchestrator 不缓存一个 authority 长期使用。

规则：

```text
每次新增 submit 前：
  validate current authority
```

如果失效：

```text
PLACE / REPLACE(new leg)
→ 不执行
```

但：

```text
CANCEL
→ 仍执行
```

如果 authority 过期，可以重新走：

```text
collect evidence
→ readiness
→ issue new authority
```

但不能自动绕过 blocker。

---

## 9. Prediction 失效语义保持 MakerPolicy 原样

Prediction stale 时：

```text
新增 exposure 禁止
reduce-only 可以继续
```

orchestrator 不额外再解释 prediction。

尤其不能：

```text
prediction missing
→ orchestrator cancel all
```

因为 P0001.7.1 已明确：

```text
降险路径不能被 prediction outage 阻断
```

---

## 10. Market unhealthy

如果市场数据不健康：

MakerPolicy 已会产生：

```text
MARKET_UNHEALTHY
```

orchestrator 根据 QuoteAction 执行：

```text
CANCEL existing increasing-risk quote
```

不自行创造第二套 market gate。

---

## 11. UNKNOWN exposure

如果：

```text
tracker.unresolved_order_count > 0
or uncertain_exposure > 0
```

新增 exposure 必须停。

现有 RiskGate / MakerPolicy 已覆盖。

orchestrator 只负责：

```text
触发 reconciliation
```

不要自己把 LOST 当 canceled。

---

## 12. User Stream 接线

Private runtime 的：

```text
ORDER_TRADE_UPDATE
```

必须统一走：

```text
adapter.bridge_user_event()
→ adapter.poll()
→ ExecutionEngine.on_events()
```

不要：

```text
private runtime
→ 直接改 Tracker
```

保持 adapter 是 Binance execution fact 的翻译边界。

---

## 13. Poll cadence

建议 loop cadence 仍与当前 Maker 主循环一致：

```text
decision cadence:
由现有配置/调用方决定
```

但 execution event drain 应更频繁：

```text
每 loop 至少 poll 一次
```

本阶段不新设高频 thread / event loop framework。

保持同步 orchestration。

---

## 14. Replacement churn

严格复用 MakerPolicy 已有：

```text
price moved
quote age
size drift
```

判断。

orchestrator 不加：

```text
“每 N 秒强制重挂”
```

否则会破坏 queue position。

当前 V3 有：

```text

```

但如果现有 MakerPolicy / lifecycle 里已表达，就只消费其输出。

```text

```

如果现有策略层尚未真正表达这个语义，则记录为后续策略 gap，不在 orchestrator 临时补业务逻辑。


在此之前：

```text
no submit
```
