# 第二轮实施记录（2026-10-04）：根因定位 + 修复 + 真实闭环进展

**状态**：**实现中（未 CLOSED）**；出现 Proposal §21 的 Stop Condition ⇒ 停止写操作并报告（见"停止项"）。

## 1. adapter-path UNKNOWN 的真实根因（已定位并修复，非扩大 timeout / 非重试）

逐项对比（base URL / timeout / timestamp / recvWindow / signing / headers / method / query 序列化 / 异常映射）
后确认：**请求组成、签名、时钟、传输全部一致**，差异只在**异常映射**：

- `BinanceExecutionRestClient` 内已有结构化映射 `_http_error(...)`（HTTP 4xx + 业务错误码 ⇒
  `ExecutionRequestRejected`；5xx/429/408/不可解析 ⇒ `ExecutionOutcomeUnknown`），
  但它的唯一调用点是 `_signed_request` 里的 `try`——而注入的 `UrllibRestFetcher`（标准实现）
  **先把任何 HTTPError 转成裸 `PrivateResponseError` 并丢弃响应体**，因此该结构化映射**不可达**，
  所有交易所明确拒绝都被 `classify_submit_response` 判为 **UNKNOWN**（submit 不落地、无 rejection evidence）。
- 实测证据（`adapter_last_submit`，已脱敏）：
  - `HTTP 400 {"code":-1111,"msg":"Precision is over the maximum defined for this asset."}`（归一化缺失导致）
  - `HTTP 400 {"code":-5022,"msg":"...Post Only order will be rejected..."}`（GTX 会成交 ⇒ 交易所拒绝）
  - 两者当时都被误判为 **UNKNOWN**；venue 无订单、自然无 ack。

**修复**（最小、结构化、可回归）：
1. `UrllibRestFetcher` 新增 additive `expose_http_errors`（默认 `False`，既有行为不变）：

## 1. 根因（已修复，含现场证据）

`adapter-path UNKNOWN` 的真因是**写路径的结构化 HTTP 错误映射不可达**：`BinanceExecutionRestClient._http_error`
能把 `4xx + 业务错误码` 判为 `ExecutionRequestRejected`（CONFIRMED_REJECTED）、把 5xx/429 判为 UNKNOWN，
但注入的 `UrllibRestFetcher` **先把 HTTPError 转成裸 `PrivateResponseError` 并丢弃响应体**，于是映射永远不触发。

现场证据（已脱敏，写入 adapter 审计）：
```
UNKNOWN | PrivateResponseError: POST .../fapi/v1/order -> HTTP 400: {"code":-1111,"msg":"Precision is over ..."}
UNKNOWN | PrivateResponseError: POST .../fapi/v1/order -> HTTP 400: {"code":-5022,"msg":"...Post Only order will be rejected..."}
```
修复：
1. `UrllibRestFetcher.expose_http_errors`（additive，默认 False 行为不变；错误信息保留响应体）；
2. `_signed_request` 捕获 `HTTPError` → 走既有 `_http_error`；
3. 回归测试 `HttpErrorMappingTest`（-5022 → CONFIRMED_REJECTED；503 → UNKNOWN；adapter 层同样断言）；
4. 另一个真实缺陷：TESTNET 组合未注入 `OrderNormalizer`（float 精度 → `-1111`），现由真实 exchangeInfo 规则构造
   `normalizer_from_rules(rules, price_rounding, quantity_rounding)` 并同时注入 adapter 与 engine。

**修复后的真实结果**：A（GTX，passive）经统一路径 `CONFIRMED_ACCEPTED`（venue orderId `28618831020`，
tracker → OPEN），随后在 TESTNET 真实成交 0.001 BTC（≈86 USDT，D-034 限额内）。
