# P0001.11.2：RuntimeSession Production Wiring

状态：已完成
日期：2026-09-29
依赖：P0001.11.1（RuntimeSession foundation）

## 目标

把现有 `RuntimeSession` 接到真正的运行入口，使 REPLAY / PAPER / TESTNET / LIVE 的**真实运行**自动形成 `RunRecord`。
**不增加任何新业务语义。**

```text
REPLAY runner ─┐
PAPER runner  ─┼→ RuntimeSession（只监听生命周期）
TESTNET       ─┤
LIVE          ─┘
```

## 边界（人类裁决，必须极死）

- 不改 orchestrator 决策顺序；
- 不改 `MakerPolicy` / `RiskGate` / `ExecutionEngine`；
- 不让 `RuntimeSession` 成为交易 Owner；
- **不重新实现 stop**：live 的 `orchestrator.stop()` 仍是原 Owner，`RuntimeSession` 只在其**完成之后** finalize run；
- stop 失败或异常 ⇒ `INCOMPLETE`，**绝不能记 `COMPLETED`**；
- 只监听生命周期：start / graceful stop / abnormal termination。

## 成功标准

1. REPLAY 自动登记；
2. PAPER 自动登记；
3. TESTNET 自动登记（允许只读/安全结构验证）；
4. LIVE wiring 存在且不改变交易行为（结构验证即可，不需要 Mainnet 实盘）；
5. stop 失败 ⇒ `INCOMPLETE`（绝不 `COMPLETED`）；
6. 全量测试不回归。

### 遗留建议（人类已指出，本阶段不阻塞）

`INCOMPLETE` 目前的读侧语义是"created but no finalization"：**正在健康运行**的实例，外部读取者会看到 `INCOMPLETE`，
UI 上可能被误读为崩溃。建议后续（不属本阶段）引入显式 `CREATED / RUNNING / COMPLETED / INCOMPLETE`
或由 live session overlay 提供 active 状态；本阶段**未**改动该语义（未授权）。

### 过程中修正的两个缺陷（属本 Slice 验收范围）

1. `PROBEX_RUN_REGISTRY_DIR` 被忽略（默认值写成字面量）⇒ 改为默认读 env；复验：日志显示 `/tmp/probex_s1d/runs` ✓。

### 与 F-10 的边界（Slice 2 负责）

## Closure Slice 2 — Real Run Lifecycle（2026-09-29，已完成并复验）

来源：审计 F-02（BLOCKER）与 F-10。收窄实现方式（人类要求）：`runtime/assembly.py` 只做 **composition root**，
feed/domain 逻辑全部复用既有模块或下沉到 provider 边界。

### 落地

| 文件 | 内容 |
| --- | --- |
| `storage/run_registry.py` | **active marker（F-10）**：`active.json`（与 run 同一持久化域，`temp→fsync→replace→fsync(dir)` 原子更新）；`mark_active` / `clear_active(run_id)`（只清自己的）/ `active_marker` / `active_run_id()`。liveness 判据**优先进程身份**（marker 的 pid + `os.kill(pid,0)`），**不使用 TTL 作为 RUNNING 的唯一真相**。读侧：active + 无 finalization ⇒ `RUNNING`；无 marker 或 pid 已死 ⇒ `INCOMPLETE`；有 finalization ⇒ `COMPLETED`（durable 语义未变） |
| `runtime/provider.py`（新） | `MarketFeedProvider`：消费 event store → `ReplaySource` → 既有 `MarketBook` / `FeatureEngine` → 既有 `BoundedMarketHistory`；PAPER 额外构造既有 `PaperBroker`+`OrderManager`（**不驱动策略、不伪造订单**）。三个最小 adapter（book snapshot / health segment / trade print）只做字段搬运，放在本 provider 边界内 |
| `runtime/wiring.py` | `SessionHost.start()` 写 active marker；`finish()` / `terminate()` / 异常路径清除 marker（F-10 的接线） |
| `runtime/assembly.py` | 收窄为 composition root：解析 profile → 构造既有 provider/投影 → 启动 SessionHost → 管理生命周期。**移除了 assembly 内的 market snapshot/health/trade 转换实现** |
| CLI | `--event-store` 对 REPLAY/PAPER 必填（真实运行）；display bounds 从 `--config-file`（`source=FILE`，CLI `--config` 覆盖）读取，**不强迫每次手输**；缺失 ⇒ 显式报错，不发明技术默认值 |
| 测试 | `tests/unit/test_runtime_wiring.py` +6（active⇒RUNNING / graceful 清除⇒COMPLETED / abnormal⇒INCOMPLETE / 死 pid 不算 active / 只清自己的 marker）+ 更新 1 条旧期望（owner stop 期间读侧由 INCOMPLETE → RUNNING，即 F-10 语义）；`tests/integration/test_runtime_assembly_startup.py` +3（真实 feed 消费、PAPER 使用既有 paper 链路且不产生订单、REPLAY/PAPER 共用市场路径） |
