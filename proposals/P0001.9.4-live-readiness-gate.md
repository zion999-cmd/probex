### 0.3 阈值与数值

`ReadinessPolicy`（`max_clock_uncertainty_ms` / `max_median_private_lag_ms` / `max_calibration_age_ms` /

### 0.5 时钟校正公式符号更正（2026-09-28 人类裁决，窄修）

本阶段实现最初把校正写成 `corrected = raw − offset`，**符号反了**。正确且已落地的形式：

```text
offset_ms = 交易所时钟 − 本地时钟            （ServerTimeOffset 既有语义）
corrected_lag_ms = receive_ts − event_ts + offset_ms    （= raw + offset）
```

反例（人类给出）：交易所快 200 ms、真实延迟 20 ms ⇒ `event_ts=1200`、`receive_ts=1020`
⇒ raw = −180 ⇒ corrected = **+20 ms**（旧写法会得到 −380 ms）。
`uncertainty_ms` **单独保存**，不从 corrected lag 中加/减。
已新增符号方向单测：`offset=+200/raw=−180 → 20`、`offset=−100/raw=+130 → 30`、`offset=0/raw=25 → 25`。

### 0.6 本阶段遗留的两处"裸输入"（记录，不阻塞）

`market_ready` 与 `mainnet_private_validated` 目前由调用方传入 `bool` / 声明事实。P0001.9.4 阶段可接受，
但**真实放单阶段必须改为受控 runtime / 验收记录生成的 typed evidence**（见 D-043），
不允许任意调用方传 `True` 就获得 `LIVE_READY`。

### 0.4 与 RiskGate 的边界

`LiveReadinessGate` = session/deployment 前置条件；`RiskGate` = 逐 OrderProposal 判定。
`LIVE_READY` **不得**绕过 `RiskGate`（readiness 包无任何执行/网络能力，SC-11 由静态测试固定）。

2. baseline 后 peak_equity=None 不再被 RiskSnapshot 变成当前 equity；drawdown_pct=None。

5. Paper / Replay 的 available-balance 现有语义不变。
6. Live risk policy 缺任何强制配置 → BLOCKED:RISK_LIMITS_NOT_CONFIGURED。
7. raw lag 为负时，能够输出 corrected lag + offset + uncertainty，而不是解释为负网络延迟。
8. clock 未测量 / 过旧 / uncertainty 超阈值 → BLOCKED。
9. Testnet 已验证证据不能使 Mainnet LIVE_READY。
10. MAINNET_PRIVATE_NOT_YET_VALIDATED → Mainnet 明确 BLOCKED。
11. LIVE_READY 不调用任何 submit/cancel，也不绕过 RiskGate。
12. Testnet 上完整 readiness runner 给出可解释结果；如果因历史风险未知而 BLOCKED，也视为正确验收。
