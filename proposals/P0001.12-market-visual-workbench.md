P0001.12：Market Visual Workbench
状态：已完成
日期：2026-09-29
依赖：P0001.10、P0001.11、P0001.11.2
目标
把 Probex 已经拥有的 L2 / trades / market-state / health / replay 数据，变成真正可观察、可回放、可解释的市场工作台。
本阶段不增加新的交易逻辑，重点是：
1. 看见盘口结构。
2. 看见盘口随时间如何变化。
3. 看见策略使用的市场特征。
4. 看见数据异常、gap、resync 对市场状态的影响。
5. 能在 Replay 模式下按时间回看完整市场演化。
目标不是做 TradingView，而是做 Probex 自己的微观结构工作台。
背景
当前 Probex 已经拥有：
BookSnapshot
BookDelta
TradePayload
OrderBook / MarketBook
BookHealth
MarketState
OFI / imbalance / spread / microprice 类特征
ReplayClock
ReplaySource
Event Store

但 UI 现在主要还是“数字表”。
也就是说：
数据丰富度     很高
可视化表达     很弱

外部 lob-engine 类项目最值得吸收的不是撮合内核，而是：
depth heatmap
time playback
microstructure panels
quality overlays

架构
Existing Market Owners
        │
        ├── Event Store
        ├── ReplaySource
        ├── MarketBook
        ├── MarketState
        └── BookHealth
        │
        ▼
Market Visualization Projection
        │
        ├── depth timeline
        ├── trade timeline
        ├── feature timeline
        ├── health timeline
        └── replay cursor
        │
        ▼
Product API
        │
        ▼
Market Workbench UI

关键原则：
Visualization projection 只读，不成为新的 market truth。

设计
1. Market Timeline Projection
新增只读市场时间序列投影。
建议结构：
MarketTimelinePoint
├── ts
├── best_bid
├── best_ask
├── mid
├── spread
├── microprice
├── imbalance
├── ofi
├── book_health
├── market_generation
└── data_quality

只来自现有 Owner。
不得在 UI 浏览器里重新推导市场事实。
2. L2 Depth Heatmap
Market 页面增加深度热图。
横轴：
time

纵轴：
price

强度：
visible resting quantity

同时叠加：
best bid
best ask
mid
trade prints

重要约束：
热图只是盘口可视化，不得把 depth 消失解释成成交。

继续遵守已有 D-025：
L2 change ≠ fill evidence

3. Replay Playback
增加 Replay 控件：
Play
Pause
Step
Speed
Seek

支持例如：
0.25x
0.5x
1x
2x
5x
10x

但 replay cursor 必须由：
ReplayClock / ReplaySource

驱动。
不能由前端自己“模拟时间”。
4. Replay Seek
这一点要谨慎。
第一版如果现有 Event Store 没有高效随机定位能力，不要为了 UI 重构 Event Store。
允许采用：
restart replay
→ fast-forward to target ordinal/timestamp

作为第一版 seek。
性能优化以后再做。
5. Market Feature Panels
至少展示现有已经进入 MarketState 的特征：
spread
microprice
imbalance
OFI

如果当前 MarketState 没有某项，不为了画图新增交易特征。
也就是说：
P0001.12 只把已有 trading facts 可视化。

VPIN / Kyle λ 等先不进入本阶段。
6. Data Quality Overlay
这是我认为非常重要的一块。
把这些事实直接画在时间线上：
HEALTHY
DEGRADED
STALE
INVALID
gap
resync
generation change

例如：
--------- market timeline ---------

healthy     healthy      GAP      resync      healthy
████████████████████     XXXXXX    |||||       ██████

这样以后看到策略突然停止报价，不需要翻日志猜。
7. Trade Overlay
真实 aggressor trade 显示在盘口时间线上：
BUY aggressor
SELL aggressor
price
quantity
timestamp

它也能帮助理解现有 queue/fill simulator 为什么认为某订单可能成交。
但仍然：
trade visualization ≠ synthetic fill

8. Quote / Decision Overlay
把已有策略决策作为 overlay：
PLACE
KEEP
CANCEL
REPLACE
NONE

显示：
quoted price
side
decision_id
reason

这样可以真正看到：
市场怎么变
→ Jev 怎么判断
→ MakerPolicy 为什么报价
→ 为什么后来撤单

不新增策略逻辑。
9. Execution Overlay
如果存在真实或模拟订单，可以显示：
order accepted
partial fill
fill
cancel
lost
unknown

全部来自现有 ExecutionEvent。
UI 不推测状态。
10. Workbench Mode
Market 页面建议形成三个视图：
LIVE
REPLAY
RUN REVIEW

但不是三套系统。
它们都读同一种 projection。
区别只是数据源：
LIVE       ← live market stream
REPLAY     ← ReplaySource
RUN REVIEW ← recorded run/event data

API
建议新增：
GET /api/v1/market/timeline
GET /api/v1/market/depth
GET /api/v1/market/trades
GET /api/v1/market/health
GET /api/v1/runs/{run_id}/market

Replay 控制如果涉及产品写行为，不建议直接放进现有只读 Product API。
第一版可以设计成：
local replay session control

并明确：
只能控制 REPLAY runtime，不能控制 LIVE execution。

若做 POST：
POST /api/v1/replay/play
POST /api/v1/replay/pause
POST /api/v1/replay/seek

这些属于“simulation control”，不是交易 write path。
但建议单独命名和隔离。
UI 信息架构
Market 页面变成：
┌────────────────────────────────────────────┐
│ Runtime / Mode / Symbol / Health / Blocker │
├────────────────────────────────────────────┤

数据量与降采样
这是本阶段必须主动处理的问题。
不能把全部 L2 delta 原样塞给浏览器。
需要 bounded projection，例如：
max time window
max price levels
max points
server-side downsampling

建议配置显式，例如：
window_seconds
price_levels
max_points
bucket_ms

但这些只是显示参数，不影响交易事实。

- Market timeline projection

当前项目一直坚持 stdlib-only，如果继续坚持，那第一版可以先用：
Canvas / SVG

不要为了图表直接引入大型前端框架。
成功标准
1. 可以在 UI 看到 L2 depth 随时间变化。
2. best bid / ask / mid 与 MarketBook 在同一时刻一致。
3. trades 来自真实 TradePayload，不从 book delta 猜。
4. replay 可以 play / pause / step。
5. replay speed 不改变事件顺序。
6. seek 后得到的 book state 与从头 replay 到同一位置一致。
7. spread / microprice / imbalance / OFI 来自既有 Owner，不在浏览器重算。
8. gap / resync / health transition 可视化可见。
9. MakerDecision 可以叠加到对应时间点。
10. ExecutionEvent 可以叠加到对应订单。
11. UNKNOWN / INVALID 状态不能被绘制成正常 0 值。
12. UI 数据量有明确上限，不能无限加载全部 L2。
13. REPLAY control 无法作用于 TESTNET/LIVE execution。
14. 不改变任何交易决策与执行语义。
15. 全量测试不回归。
