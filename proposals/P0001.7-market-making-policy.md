## 0. 本阶段的固定契约（供审查）

### 0.1 策略层的输入 / 输出

```text
输入：MarketState + PredictionRecord(可为 None) + Position + RiskSnapshot + 现有挂单 + remaining_risk_budget + KillSwitchMode
输出：MakerDecision（不含任何订单生命周期动作）
```

- 策略层**只产出决策**：`OrderProposal`（永远 `post_only=True`）、要撤的 `client_order_id`、以及 KEEP/CANCEL/REPLACE/PLACE/NONE 分类。
- 真正撤单 / 重挂由 P0001.6 的 `OrderManager` 执行（cancel-before-replace 语义不变）。
- 策略层不写 Accounting、不改 Execution 状态机、不联网、不使用 wall-clock（时间只来自 `RiskSnapshot.now_ms`）。

### 0.2 四个独立决策模块

| 模块 | 职责 | 关键规则 |
| --- | --- | --- |
| `pricing.py`（QuotePrice） | 挂价 | 买价 ≤ best_bid、卖价 ≥ best_ask；默认挂 best bid / best ask；只允许**后退** 0..N ticks，永不穿价、永不做 taker；价格对齐 tick 网格（买向下取整、卖向上取整） |
| `sizing.py`（QuoteSize） | 挂量 | `base_size × inventory_factor × confidence_factor × risk_budget_factor`，四个 factor 全部有上下界；按 `quantity_step` 向下取整；低于 `min_quote_size` 不下单 |
| `inventory.py`（InventoryBias） | 库存偏置 | `target_position` 显式（第一版市场中性 → 传 0）；净多头 → 买侧缩量 + 买侧多退，卖侧放量且不后退；净空头对称 |
| `lifecycle.py`（QuoteLifecycle） | 生命周期 | KEEP / CANCEL / REPLACE / PLACE / NONE，优先级见 0.5 |

### 0.3 数值语义（全部由调用方注入，无默认值）

所有阈值 / 尺寸 / 周期都是**必填构造参数**（§12：实现方不得自行决定经济参数）。策略层不发明任何数值。

| 参数 | 含义 |
| --- | --- |
| `tick_size` / `quantity_step` / `min_quote_size` / `base_size` | 交易所网格与基础下单量 |
| `minimum_edge_bps` | cost floor：**新增暴露**的报价相对 mid 的方向性优势（bps）下限 |
| `max_back_ticks` | 允许的最大后退 tick 数 |
| `adverse_selection_block` / `adverse_selection_retreat` | 对应侧 adverse-selection 概率 ≥ block → 该侧禁止新增暴露；≥ retreat → 后退 1 tick |
| `imbalance_retreat` / `microprice_skew_retreat_bps` / `predicted_move_retreat` | 失衡 / microprice skew / 预测不利方向概率阈值，各自贡献 1 tick 后退 |
| `prediction_horizon_ms` | 消费哪个 horizon 的分布（必须存在于记录中） |
| `target_position` / `inventory_scale` / `inventory_size_strength` / `inventory_retreat_ticks_max` | 库存控制 |
| `size_factor_min` / `size_factor_max` / `confidence_ref_low` / `confidence_ref_high` / `confidence_factor_min` / `risk_factor_min` | 乘数上下界 |
| `price_move_ticks_replace` / `max_quote_age_ms` / `size_drift_tolerance` | 生命周期触发阈值 |

### 0.4 Prediction 的消费方式

- 只消费：`future_return` 分布（某一 horizon）、`buy/sell_adverse_selection`、`derived_confidence`、`expires_at`（freshness）。
- **不消费** `buy/sell_fill_probability` 做任何乘数（SC-5：高 fill probability 可能正是 adverse selection 高）；
  fill probability 只允许出现在 telemetry / 后续标定，不得进入数量公式。
- **禁止** Prediction → BUY / SELL 的直接映射：方向性影响仅通过「后退 tick 数」「哪一侧允许报价」「confidence factor（有界）」表达。

### 0.5 生命周期优先级（首个命中者决定动作）

```text
1. 无现有挂单 / 现有已终态 → PLACE(INITIAL_QUOTE) 或 NONE
2. 现有挂单 LOST            → KEEP（状态未知，不重复下单、不假设可撤）
3. 现有挂单 PENDING_CANCEL  → KEEP（撤单已在途中，不重复撤）
4. cancel_all（HALT_ALL）   → CANCEL
5. 该侧被禁止（禁止原因）    → 现有单是 reduce-only → KEEP；否则 CANCEL
6. 该侧当前不应有报价        → CANCEL
7. 期望价与挂价相差 ≥ price_move_ticks_replace → REPLACE(PRICE_MOVED)
8. 挂单年龄 > max_quote_age_ms → REPLACE(QUOTE_AGE_EXCEEDED)
9. 期望量与剩余量相对偏差 > size_drift_tolerance，或 reduce_only 语义改变 → REPLACE(SIZE_DRIFT)
10. 否则 → KEEP(WITHIN_TOLERANCE)
```

### 0.6 全局门（fail closed）

| 条件 | 新增增加暴露的报价 | 现有报价 | 触发码 |
| --- | --- | --- | --- |
| `KillSwitchMode.HALT_ALL` | 禁止 | **全部**撤 | `KILL_SWITCH` |
| `KillSwitchMode.REDUCE_ONLY` | 禁止 | 仅撤增加暴露的 | `KILL_SWITCH` |
| `state.quality.tradeable == False` | 禁止 | 仅撤增加暴露的 | `MARKET_UNHEALTHY` |
| 无 PredictionRecord / 已过期 / 缺 horizon | 禁止 | 仅撤增加暴露的 | `PREDICTION_STALE` |  ← **该行语义已被人类 2026-09-28 裁决修正，见 §0.10**
| `RiskSnapshot.unresolved_order_count > 0`（P0001.6.1） | 禁止 | 仅撤增加暴露的 | `UNKNOWN_EXPOSURE` |

- **reduce-only 报价永远允许**（降低风险是安全的），但取消类动作仍然生效。
- 无 prediction 时 cost floor 无法评估 → 新增暴露一律禁止（这是 §0.3 与 fail-closed 纪律的**推导结果**，不是新发明的业务规则）。

### 0.7 Reduce-only 判定（机械推导，非业务判断）

`reduce_only = (SELL and position.qty > target_position) or (BUY and position.qty < target_position)`；
且 reduce-only 的数量上限为 `|position.qty − target_position|`（保证 proposal 不会变成增加暴露）。

### 0.8 附加动作说明

`QuoteAction` 在提案要求的 KEEP / CANCEL / REPLACE 之外必须有 `PLACE`（该侧尚无挂单且需要报价）
与 `NONE`（该侧不应有挂单且当前也没有）—— 否则无法表达首次报价与「空着」这两种状态。

## 0.10 人类裁决（2026-09-28）与待办子阶段

人类对 §1「刻意的设计取舍」的三条逐项裁决：

| # | 我的取舍 | 裁决 | 说明 |
| --- | --- | --- | --- |
| ② | `KillSwitchMode.REDUCE_ONLY` 允许新挂 reduce-only | **保留** | 与原实现一致 |
| ③ | 库存偏多时买侧「缩量 + 后退」而非立刻停报 | **保留** | 以后再加明确的仓位阈值参数 |
| ① | 无/过期 prediction 时不允许**新增** reduce-only | ❌ **不接受** | 见下 |

**裁决 ① 的理由（人类原话要点）**：若已持仓而 Jev 故障或 prediction 过期，当前实现会阻断**新增** reduce-only 报价；
如果此时恰好没有存量退出挂单，系统就**无法主动降低风险**，这与此前 Risk 层「降低 exposure 应优先允许」的原则冲突。

**因此本提案的 SC-2 语义被修正为（人类授权，§7.1）**：

- prediction 缺失 / 过期 / 缺 horizon 时：
  - **禁止**新增**增加暴露**的报价（原语义保留）；
  - **必须允许新增 reduce-only 报价**（新语义）——即 `risk` 方向的主动降险不得被 prediction 可用性阻断；
  - 已有的增加暴露报价仍应被撤掉；已有的 reduce-only 报价保留。
- 无 prediction 时 reduce-only 报价的价格/规模仍必须满足：不穿盘口（post-only）、库存方向正确、
  受风险预算与 RiskGate 约束；cost floor 依旧只适用于**增加暴露**的报价。

**当前落盘状态与差距（如实记录）**

- 已实现的 `MakerPolicy` 在 `PREDICTION_STALE`（以及 `MARKET_UNHEALTHY` / `UNKNOWN_EXPOSURE`）下
  `allow_new_reducing = False`，即 **reduce-only 也不会新增** —— 与修正后的 SC-2 不符。
- 待办子阶段（需落盘独立提案）需定义并实现：
  1. 哪些全局门允许「新增 reduce-only」（至少 `PREDICTION_STALE` 必须允许；`MARKET_UNHEALTHY` / `UNKNOWN_EXPOSURE` / `HALT_ALL` 需人类明确）；
  2. 无 prediction 时 reduce-only 报价的定价与规模依据（本提案 §0.2 的纯盘口定价 + 库存方向是否足够）；
  3. 对应的 fault 测试（无挂单 + 持仓 + prediction 过期 → 必须产生 reduce-only 报价）与 SC-2 的验收更新。
- **子阶段已落地（2026-09-28）**：`P0001.7.1` 实现并验收（`allow_new_reducing=True`、`fresh_prediction()` 不伪造预测）；
  本提案因此置为「已完成」。子阶段落地时的两条**待明确项**按最小改动处理（理由见 P0001.7.1 §1「刻意保留」）：
  `MARKET_UNHEALTHY` / `UNKNOWN_EXPOSURE` / `HALT_ALL` 仍阻断全部新增报价（含 reduce-only）；
  有新鲜 prediction 时 `adverse_selection_block` 仍禁止该侧（含 reduce-only 侧）新增报价。两者作为观察项待人类裁决。

## 2. 原 P0001.7 提案文本（原样保留）

目标
建立 Maker 策略层，把：
MarketState + Prediction + Position + Risk context

转换为：
OrderProposal

只负责“报什么价、报多少、何时撤/重挂”，不负责订单生命周期和交易所交互。
背景
现在链路已有：
MarketData
→ Feature / MarketState
→ Jev Prediction
→ Accounting / Risk
→ Execution / PaperBroker

还缺策略层：
MarketState + Prediction
→ Maker quoting decision
→ OrderProposal

这一层必须和 Execution 分开，否则以后 cancel race、partial fill、reconciliation 会污染策略逻辑。
架构
MarketState
Prediction
Position
RiskSnapshot
    │
    ▼
MakerPolicy
    │
    ├─ QuotePrice
    ├─ QuoteSize
    ├─ QuoteLifecycle
    └─ InventoryBias
    │
    ▼
OrderProposal
    │
    ▼
RiskGate
    │
    ▼
ExecutionEngine

设计
核心拆成四个独立决策：
QuotePrice
QuoteSize
QuoteLifecycle
InventoryBias

不要写成一个巨型 decide()。
QuotePrice 负责基于 best bid/ask、spread、microprice、prediction、cost floor 决定 maker price；第一版只允许挂在盘口内或盘口边缘，不允许主动穿价。
QuoteSize 负责基于基础下单量、当前 position、max exposure、remaining risk budget 缩放数量。Prediction 不能直接决定数量，只能影响倾向。
InventoryBias 负责根据已有净仓位调整双边报价。例如已有 long 时：
- 买侧更保守
- 卖侧更积极
  但不能直接绕过 RiskGate。
QuoteLifecycle 决定：
- 什么时候保留旧单
- 什么时候撤单
- 什么时候重报价
- 什么时候因为 prediction stale / market unhealthy / spread 变化而撤单
Prediction 使用方式
Jev 输出是概率，不是交易指令。
策略只允许消费：
future return distribution
buy/sell adverse-selection probability
buy/sell fill probability
provider freshness

禁止：
Prediction → BUY
Prediction → SELL

必须经过本地 policy。
Cost Floor
任何新增 exposure 的 maker quote，至少满足：
expected directional edge
>
fees
+ adverse selection buffer
+ execution/slippage buffer

这里先不实现严格 EV，因为五分类 bucket 还没有数值化。

## 2. 观察项（Observation，未实施，待人类裁决；§31）

1. **`UNKNOWN_EXPOSURE` 与 reduce-only 的不一致**：`RiskGate`（P0001.6.1）在「存在资料不足订单」时只拒绝**增加暴露**的订单、
   放行 reduce-only；而 MakerPolicy 的全局门在该条件下阻断**全部**新增报价（含 reduce-only）。同一原则（降险优先）在两层的表现不一致。
   若人类认同降险优先，应新增一个小提案把该门改为 `allow_new_reducing=True`。
2. **`adverse_selection_block` 与 reduce-only 的不一致**：有新鲜 prediction 且该侧 adverse-selection 超 block 时，MakerPolicy 会禁止该侧
   （含本可降险的 reduce-only 侧）新增报价。P0001.7 的 SC-4 未区分 reduce-only，本阶段按既有语义保留。
3. **prediction 中断引起的 replace churn**：无 prediction 时 `confidence_factor` 取有界下界，可能导致已存在的 reduce-only 挂单因
   `SIZE_DRIFT` 被 REPLACE（撤单窗口内暂时没有出口报价）。当前实现依赖正常生命周期（SC-5 允许 KEEP 或 REPLACE）；
   若人类希望「中断期间冻结已有 reduce-only 挂单」，需要一个明确的新规则（本阶段未自行发明）。
