# P0001.14：Runtime Decision Loop Integration

**状态**：已完成
**日期**：2026-10-03
**依赖**：P0001.11、P0001.12、P0001.13

## 目标

把 Probex 当前已经存在但彼此分离的运行组件：

Market
→ Prediction
→ Strategy
→ Risk
→ Readiness
→ Execution
→ Accounting

接成真实 runtime 决策闭环。

本阶段重点是完成工程闭环，不要求立即覆盖完整业务能力。

完成后：

- REPLAY 能运行观察/决策链；
- PAPER 能运行完整模拟执行链；
- Prediction provider 不可用时必须诚实显示 UNAVAILABLE；
- Strategy / Risk / Execution 不再依赖测试 harness 人工注入；
- Product trace / UI / Assistant 能读取真实 runtime facts。

设计
1. RuntimeDecisionLoop
新增正式 runtime decision loop。
职责：
- 接收 MarketState；
- 根据 state hash / prediction TTL / cadence 判断是否需要重新评估；
- 调用 PredictionRuntime；
- 调用 MakerPolicy；
- 将交易意图送入 ExecutionEngine；
- 维护生命周期；
- graceful stop 时停止自己的 async loop/thread。
不允许：
- 自己计算 prediction；
- 自己计算风险；
- 自己生成 BUY/SELL；
- 直接调用 Binance；
- 成为新的业务 Owner。
2. PredictionRuntime
PredictionRuntime 保持唯一 prediction owner。
正式调用：
PredictionRuntime.submit(state)

输出 PredictionRecord。
如果 provider 不可用：
prediction = UNAVAILABLE

禁止：
- 伪造 50%
- 固定 bullish/bearish
- 用价格方向冒充预测
测试可以使用正式 provider contract 的 FakeProvider。
但 FakeProvider 不能作为产品验收中“真实 prediction 已工作”的证据。
3. MakerPolicy
MakerPolicy 保持唯一策略 owner。
正式调用已有：
MakerPolicy.decide(...)

可以自然产生：
- PLACE
- KEEP
- CANCEL
- REPLACE
- NONE
不得新增 demo strategy。
不得为了验收强迫下单。
如果缺业务配置：
MakerPolicy = unavailable / absent

必须诚实暴露。
4. RiskGate
所有增加风险敞口的交易意图继续必须经过：
ExecutionEngine.submit()
→ RiskGate.evaluate()

Risk reject：
→ 不创建订单
→ 写 risk rejection
→ 进入 evidence trace
→ Product UI 可解释

不新增第二套风险判断。
5. Remaining Risk Budget
remaining_risk_budget 不允许由 assembly 或 RuntimeDecisionLoop 计算。
由 Risk Domain 提供 canonical read-only provider。
计算语义必须与现有 RiskGate increasing-exposure checks 一致，综合已有：
- position exposure
- notional limits
- quantity limits
- open-order exposure
- available balance
- effective leverage
事实不足时：
UNKNOWN / fail closed

不能简单用：
max_position_notional - current_position

除非 Risk Domain 的正式语义明确如此。
6. PAPER Readiness
PAPER 不使用 LiveReadinessGate 作为 submit authority。
原因：
现有 LiveReadinessGate 的 contract 属于 TESTNET / MAINNET live execution，需要：
- private connectivity
- recovery
- clock
- HWM
- live readiness scope
PAPER 没有这些 live semantics。
因此 PAPER 记录：
readiness.applicable = false
reason = PAPER_LIVE_READINESS_NOT_APPLICABLE

它进入 causal trace，但不阻断 PAPER submit。
TESTNET / LIVE 仍保持：
Risk allow
→ LiveReadinessGate
→ authority
→ submit

BLOCKED / UNKNOWN 继续 fail closed。
不修改 LiveReadinessGate 原业务规则。
7. 唯一 PaperBroker
移除 MarketFeedProvider 内错误创建的 PaperBroker。
最终：
MarketFeedProvider
→ 只负责 market facts

ExecutionEngine
→ 唯一 PaperBroker

一个 PAPER runtime 中：
PaperBroker instance count = 1

Market data 和 execution/account state 不允许存在两个独立世界。
8. Production Product Providers
assembly 必须接通真实 provider：
- prediction
- maker_decision
- risk_snapshot
- risk_limits
- readiness
- prediction_fresh
- risk_rejects
不再允许正式 runtime 使用：
lambda: None

Product layer 只读取真实 runtime facts。

TESTNET / LIVE

沿用既有：
- D-034
- mode gate

- UNKNOWN submit semantics
- no auto retry
不新增 LIVE 自动交易能力。
