# P0001.14：Runtime Decision Loop Integration

**状态**：已完成（2026-10-03；人类裁决授权的连续实施）
**授权**：人类当前会话明确指令 —— 按已批准内容创建本文件、`currentProposal = "P0001.14"`、连续实现。
**日期**：2026-10-03
**依赖**：P0001.11、P0001.12、P0001.13

## 目标

把 Probex 当前已经存在但彼此分离的：

Market → Prediction → Strategy → Risk → Readiness → Execution

接成真实 runtime 决策闭环。本阶段不是发明新策略，也不是增加新的预测模型，而是让已有 Owner 在同一个
ProductRuntime 生命周期中真正协作。

## 人类裁决（2026-10-03，本会话）

1. **Proposal / 范围**：本阶段**不**加入完整 Instrument/Venue Domain 重构（股票/期货/Crypto + 多供应商正式抽象
   留到 **P0001.15**）。P0001.14 只保留**最小 execution connector seam**，避免 Runtime Decision Loop 直接依赖
   Binance/Paper 具体实现。
2. **PAPER readiness = 方案 A**：PAPER **不**经 `LiveReadinessGate` 作为 submit authority；causal chain 仍记录
   readiness stage（`UNAVAILABLE` + `PAPER_LIVE_READINESS_NOT_APPLICABLE`，现有状态模型无 NOT_APPLICABLE），
   但它**不阻止** PAPER submit。TESTNET/LIVE 才必须 `Risk allow → LiveReadinessGate → authority → submit`，
   `BLOCKED/UNKNOWN ⇒ no submit`。**不修改** `LiveReadinessGate` 既有业务规则。
3. **PAPER risk budget**：禁止 assembly/runtime 自行计算风险预算。`remaining_risk_budget` 必须由 **Risk domain**
   的正式 provider 提供（复用 `RiskLimits` / `RiskSnapshot` / 当前持仓暴露 / 挂单敞口）。由 Risk domain 计算
   剩余可用预算并**只读暴露**，Runtime/DecisionLoop 只消费结果。若 Risk domain 缺少形成 canonical remaining
   budget 的事实 ⇒ 在该点停止并报告缺失字段，**不允许发明风险数学**。
4. **Prediction provider**：`tests/fakes.py::FakeProvider` 允许用于 unit/integration wiring test，**禁止**用于
   最终产品级验收后声称"真实 prediction provider 已工作"。真实 REPLAY/PAPER 运行：若 SystemOne/Jev provider
   可用 ⇒ 用正式 `PredictionRuntime` provider；若 credential/业务阈值当前不可用 ⇒ `PredictionRuntime` 必须真实
   接线、provider 状态明确 `UNAVAILABLE`、MakerPolicy 按既有规则自然 HOLD/NONE、UI/Activity/Assistant 显示真实
   UNAVAILABLE 原因。**不伪造** 50% / bullish-bearish / 人为触发 BUY-SELL。
5. **Instrument/Venue 最低限度**：`MarketFeedProvider` 不拥有 `PaperBroker`；execution path 只有唯一 `PaperBroker`；
   `DecisionLoop` 不直接 import Binance adapter；`ExecutionEngine` 保持现有 adapter/connector seam。**不**实现
   EQUITY/FUTURE/CRYPTO domain hierarchy、IBKR/CTP/OKX、多 venue、多 asset-class（→ P0001.15）。

### CLOSED 条件（按裁决调整）

必须：Market → `PredictionRuntime` → `MakerPolicy` → Risk → PAPER Execution wiring 真正存在；MakerPolicy 自然产生
decision（含 HOLD/NONE）；PAPER 唯一 PaperBroker；RiskGate 必经；PAPER readiness 记录但不作为 live gate；
TESTNET/LIVE readiness 语义不变；prediction unavailable 时诚实显示；graceful shutdown；Product providers 不再是
`lambda: None`；trace/UI 能读取真实 runtime facts；detached full suite green；commit/push。

"自然产生真实 order/fill"仅在 prediction provider 可用 **且** MakerPolicy 条件自然满足时作为**强制**验收；
若外部 prediction provider 不可用，**不得**为完成验收使用 FakeProvider 或修改策略强迫下单。

## 架构（目标数据流）

```
MarketFeedProvider ─► MarketBook / FeatureEngine ─► MarketState
        │
        ▼
PredictionRuntime（唯一 prediction owner；async submit；TTL/backoff/scheduler 既有）
        │
        ▼
MakerPolicy.decide(...) ─► MakerDecision（PLACE/KEEP/CANCEL/REPLACE/NONE）
        │
        ▼
RiskGate（ExecutionEngine.submit 内部必经）─► allow / reject（reason_code）
        │
        ▼
Readiness（PAPER：UNAVAILABLE + PAPER_LIVE_READINESS_NOT_APPLICABLE，不阻塞；
           TESTNET/LIVE：LiveReadinessGate + authority，BLOCKED ⇒ no submit）
        │
        ▼
ExecutionEngine ─► OrderManager / OrderTracker ─►（唯一）PaperBroker
        │
        ▼
FillLedger / AccountingCore ─► Product projections（Market overlays / Activity trace / Monitor / Performance / Assistant）
```

所有阶段仍由现有 Owner 拥有业务语义；`ProductRuntime` / assembly 只负责 composition 与生命周期。

## 不包含（NOT Included）

新交易策略、新预测模型、新 Risk 规则、新 Readiness 规则、新 execution state machine、新 PaperBroker、
第二套 accounting / order owner / evidence store、参数优化器、traditional candle backtester、multi-symbol、
multi-venue、CAPITAL action、live auto trading、UI 大改版、LLM 文本进入交易热路径、为 E2E 硬编码交易结果。
Instrument/Venue Domain（含 IBKR/CTP/OKX、多 asset-class）→ **P0001.15**。

## 实施记录（2026-10-03）

**新增**

| 文件 | 作用 |
| --- | --- |
| `runtime/decision_loop.py` | 决策闭环编排（单线程 + 自有 asyncio loop；节流；写入权限只对 PAPER；readiness 只记录） |
| `runtime/maker_config.py` | 由 deployment config 构造 `MakerPolicy`（缺任一键 ⇒ `None`，不发明业务数值） |
| `risk/budget.py` | **Risk domain** 的 canonical 剩余暴露预算（与 `RiskGate._increasing_exposure_checks` 语义一致） |
| `tests/unit/test_decision_loop.py` / `test_risk_budget.py` | 编排行为 + 预算语义（含与 RiskGate 的一致性对照） |
| `tests/integration/test_runtime_decision_loop_e2e.py` | 真实装配下的 PAPER/REPLAY 闭环验收（含诚实失败路径） |

**修改**

- `runtime/assembly.py`：装配 decision loop；Product providers（`prediction` / `maker_decision` / `risk_snapshot` /
  `risk_limits` / `readiness` / `prediction_fresh` / `risk_rejects`）不再 `lambda: None`；`stop()/fail()` 先停 loop。
- `runtime/provider.py`：`MarketFeedProvider` **不再**拥有 `PaperBroker` / `OrderManager`（唯一 broker = `ExecutionEngine.manager.adapter`）。
- `product/service.py` / `product/types.py` / `product/blockers.py`：maker 决策的真实原因（`blocked_by` 或未报价侧的 trigger）
  进入 trace/UI；readiness 增加 `applicable`（PAPER/REPLAY ⇒ false）；不因 PAPER readiness 制造假 blocker；
  策略 detail 为空时使用稳定说明（不再抛 `BlockerView.message` 空串）。
- `product/reason_catalog.py`：新增 `PAPER_LIVE_READINESS_NOT_APPLICABLE` / `LIVE_READINESS_NOT_EVALUATED` /
  `RISK_BUDGET_UNKNOWN` / `RISK_BUDGET_EXHAUSTED`。
- `tests/integration/test_runtime_assembly_startup.py`：改为断言 feed 不拥有 broker + 唯一 broker 在 engine。

**验收结论**

- PAPER 闭环自然产生 `MakerPolicy` 决策（初始 `PLACE` 双边）→ `RiskGate` 逐单 allow → 唯一 `PaperBroker` 产生 2 张
  `OPEN` 订单 + ack（trace/UI 可读）；readiness 记为 `unavailable` + `PAPER_LIVE_READINESS_NOT_APPLICABLE`
  （`applicable=false`、trace `not_applicable`），**不阻断** submit（方案 A）。
- 无 mark price fact ⇒ 预算未知 ⇒ 决策 `NONE` + `RISK_BUDGET_UNKNOWN`（fail closed，不伪造）。
- prediction provider 未接线 ⇒ `absent`、无报价；`MakerPolicy` 配置缺失 ⇒ 无 decision（ABSENT，不伪造 HOLD/买卖）。
- 全量测试 **2347 passed / 0 failed / 24 skipped**。

**未达成的强制项（如实报告）**

- **真实外部 prediction provider 未接入**：`Profiles/trial-local.json` 没有全部 `MakerPolicyConfig` 业务数值，
  且 `OPENROUTER_API_KEY` / adverse-selection 阈值不在仓库内，因此产品级运行中 `PredictionRuntime` 依旧
  `UNAVAILABLE`（按裁决第 4 条，不为验收使用 FakeProvider、不修改策略强迫下单）。
- 因此"自然真实 order/fill"的**强制**验收未触发（条件未自然满足）；上述 PAPER 闭环是在
  integration test 注入 provider 契约实现 + 测试参数下验证的 wiring 证据。
- PAPER 目前**没有 mark price 来源**（既有契约明确"不使用 last trade"）⇒ 未注入 mark price 时风险事实缺失、
  `RiskGate` fail closed（这是既有业务语义，不在本阶段改动范围）。
