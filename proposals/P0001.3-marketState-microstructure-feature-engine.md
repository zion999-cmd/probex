## 1. P0001.3 实现契约

### 1.1 Included

- immutable `MarketState`（identity / time / quality / price / depth / flow / trade / return / volatility / `feature_schema_version`）
- Feature Schema（`market-state-v1`）+ 版本升级规则
- instantaneous book features（best bid/ask、sizes、mid、spread、spread_bps、microprice）
- top-N depth（N ∈ {1,5,10,20}）、L1 / depth imbalance、VAMP
- event-domain OFI（`BookMutation` → `event_ofi` / rolling OFI / `normalized_ofi`）
- return windows（1s / 3s / 5s / 15s / 30s / 60s / 300s）
- realized volatility（5s / 15s / 30s / 60s，以秒为量纲）
- rolling-window infrastructure（`TimeWindow` / `EventWindow` / `TimeSeries`）
- `DataQuality`（含 `tradeable` 闸门与 warm-up 语义）
- 缺失值语义：未知 ≠ 0
- deterministic Replay 验证

### 1.2 NOT Included

- Jev API / Jev prompt / prediction / Strategy / buy-sell-hold / Market Making
- Order / Position / Risk / Paper / Live Trading
- Live WebSocket、任何网络调用
- C++/Rust 性能下沉
- ML 特征选择、特征有用性自动判断、Feature DSL、feature database
- 技术指标库（RSI / MACD / Bollinger）
- 伪造 Trade 数据（Trade 域只提供结构，全部输出 unavailable）
- 新增任何第三方依赖

### 1.3 本阶段固定的 feature 定义（公式即契约，变更必须升级 schema）

| 名称 | 定义 | 缺失语义 |
| --- | --- | --- |
| `mid` | `(best_bid + best_ask) / 2` | 任一侧缺失 → `None` |
| `spread` | `best_ask - best_bid` | 任一侧缺失 → `None` |
| `spread_bps` | `spread / mid * 10000` | `mid` 缺失或为 0 → `None` |
| `microprice` | `(best_bid * ask_size + best_ask * bid_size) / (bid_size + ask_size)` | `bid_size + ask_size == 0` → `None` |
| `L1Imbalance` | `(bid_size - ask_size) / (bid_size + ask_size)`，range [-1, 1] | 分母 0 → `None` |
| `DepthImbalance(N)` | `(B_N - A_N) / (B_N + A_N)`，`B_N`/`A_N` 为前 N 档 size 之和 | 分母 0 → `None` |
| `bid/ask_depth_N` | 前 N 档 size 之和；档位不足 N 时取现有档位之和 | 盘口不可用 → `None` |
| `vamp` | VAMP_5：双边前 5 档的 `Σ(price*size) / Σ(size)`（仅来自盘口，非成交 VWAP） | 总 size 0 或盘口不可用 → `None` |
| `event_ofi` | 每次已应用 level mutation 的 OFI（Cont-Kukanov-Stoikov 形式）在一条 delta 内的求和 | 未应用任何 mutation → `None` |
| `ofi_h` | 时间窗内 `event_ofi` 之和 | 窗口空 → `None` |
| `normalized_ofi_h` | `ofi_h / (bid_size + ask_size)`（以当前 L1 深度归一） | 分母缺失或 0、或 `ofi_h` 缺失 → `None` |
| `book/bid/ask_update_count` | 累计已应用 level mutation 数（按方向拆分） | 恒为整数 |
| `level_additions` | 累计 `old_size == 0` 的 mutation 数 | 恒为整数 |
| `level_removals` | 累计 `new_size == 0` 的 mutation 数 | 恒为整数 |
| `return_h` | `mid(t) / mid(latest observation <= t-h) - 1` | 无该时刻或更早观测 → `None` |
| `realized_volatility_h` | `sqrt( Σ r_i² / (h/1000) )`，`r_i` 为窗内相邻观测的对数收益（每秒已实现波动率，量纲 1/√s） | 窗内观测 < 2 或 `t-h` 之前无观测 → `None` |
| `completeness` | `(price+depth+flow+returns+volatility 各段中非 None 字段数) / (这些段字段总数)` | 恒为 [0,1] |
| `history_ready` | `window_coverage_ms >= 300000`（最长 return 窗口） | 布尔 |
| `feature_ready` | `book_healthy AND history_ready` | 布尔 |
| `age_valid` | `book_age_ms is not None AND (max_book_age_ms is None OR book_age_ms <= max_book_age_ms)` | 布尔 |
| `tradeable` | `feature_ready AND age_valid`（只描述市场数据是否可用于决策，不含资金/仓位/Risk） | 布尔 |
| `sequence_contiguous` | 粘性标志：本引擎生命周期内从未出现 sequence gap | 布尔 |

其他固定选择：

- 窗口的时间轴一律来自事件时间（`exchange_ts`），不接受 `time.time()`；窗口 API 的时间戳为显式参数。
- 价格历史 horizon = 600000 ms（最长 return 窗口的 2 倍）。
- `MarketState.time.event_ordinal` = 本引擎消费事件的 0 基递增计数器。
- `sequence_contiguous` 一旦为假不再恢复；它不进入 `tradeable`。
- 盘口不健康时：price / depth / returns / volatility 全部 `None`，OFI 窗口清空并停止累积，价格历史停止写入（不沿用旧值）。
- `max_book_age_ms` 默认 `None`（本阶段不引入未经授权的年龄阈值）。

### 1.4 Success Criteria

- **SC-1** 相同 Event Store Replay 两次，产生的每个 `MarketState` 逐字段相等。
- **SC-2** `BookHealth != HEALTHY` 时所有依赖 Book 的 feature 明确 unavailable，不沿用旧值。
- **SC-3** microprice 覆盖：对称、极端 imbalance、空侧、零数量。
- **SC-4** L1 / N 档 imbalance 公式与范围固定。
- **SC-5** 人工 `5 → 7 → 5` 档位流：event-domain OFI 观测到两次变化，而 snapshot-only 净变化为 0。
- **SC-6** Rolling Window 在 Event Replay 与人工时间戳下行为一致，不依赖 wall-clock。
- **SC-7** Return lookup 永不读取目标 timestamp 之后的数据。
- **SC-8** Volatility 以秒定义，不随 event frequency 改变量纲。
- **SC-9** 历史不足时返回 unavailable 而不是 0。
- **SC-10** 公式 / 单位 / 窗口 / 缺失语义可由 `feature_schema_version` 确定。
- **SC-11** P0001.3 不 import Jev / Strategy / Execution / Portfolio / Risk。
- **SC-12** 既有 205 个测试继续通过。

## 2. 原 P0001.3 提案文本（原样保留）

# P0001.3：MarketState + Microstructure Feature Engine
状态：已提议
日期：2026-09-28
依赖：P0001.1、P0001.2
目标
建立从 canonical MarketEvent / MarketBook 到版本化 MarketState 的确定性转换层。
本阶段解决：
“在时刻 t，系统究竟知道什么？”

不接 Jev，不做交易策略。
最终要求：
MarketEvent stream
      ↓
MarketBook
      ↓
FeatureEngine
      ↓
MarketState(t)

同一份 Event Store 重放两次，必须产生逐字段一致的 MarketState 序列。
背景
现在我们已经有：
P0001.1
MarketEvent → trusted L2 Book

P0001.2
Event Store → deterministic Replay

但目前还不能直接喂 Jev。
因为 Jev V3 中的：
microprice
VAMP
imbalance
OFI
CVD
returns
volatility
trade flow

实际上混在一个状态构造函数里，而且部分数据来自定时采样。
现在要把它变成正式的市场状态层。
架构
MarketEvent
     │
     ├──────────────▶ MarketBook
     │                    │
     │                    ▼
     │                BookView
     │
     ▼
Event Feature Updates
     │
     ▼
┌────────────────────────────┐
│       FeatureEngine        │
│                            │
│ Price                      │
│ Depth                      │
│ Order Flow                 │
│ Trades                     │
│ Returns                    │
│ Volatility                 │
└──────────────┬─────────────┘
               │
               ▼
          MarketState

关键原则：
FeatureEngine 只能消费已经确认有效的市场事实。

如果：
BookHealth != HEALTHY

Book-derived feature 不得继续伪装成正常数据。
设计
1. MarketState 是 immutable snapshot
定义明确的：
MarketState

至少包含：
identity
  venue
  symbol

time
  as_of_exchange_ts
  as_of_receive_ts
  event_ordinal

quality
  book_health
  book_age
  trade_age
  completeness

price
depth
flow
trade
return
volatility

feature_schema_version

创建以后不可修改。
Jev 后面拿到的就是某一个确定的：
MarketState(t)

而不是一个正在变化的全局对象。
2. Feature 分成“状态”与“窗口”
不要全部塞进一个 dict。
Instantaneous
由当前 BookView 直接得到：
best_bid
best_ask
bid_size
ask_size

mid
spread
spread_bps

microprice

top-N bid depth
top-N ask depth
depth imbalance
VAMP

Event-derived
逐事件累积：
OFI
book update count
bid update count
ask update count
level additions
level removals

Trade-derived
当 Trade MarketEvent 后续存在时：
buy aggressive volume
sell aggressive volume
signed volume
CVD
trade count
trade intensity
VWAP

Time-series
returns
realized volatility

3. Microprice
正式定义，避免以后不同模块各写一版：
microprice =
(best_bid * ask_size + best_ask * bid_size)
/
(bid_size + ask_size)

这里的权重是对侧价格 × 本侧数量。
如果：
bid_size + ask_size == 0

返回：
None

不是 0。
4. Imbalance
明确区分：
L1Imbalance
DepthImbalance(N)

统一标准化：
(B - A) / (B + A)

范围：
[-1, 1]

不能再把不同档位定义都叫 imbalance。
至少支持：
N = 1
N = 5
N = 10
N = 20

但 Feature Schema 中档位必须固定，而不是运行时任意变化。
5. OFI：从 snapshot approximation 升级为 event-domain
这是 P0001.3 的核心。
不要继续复刻 V3 的：
每秒 snapshot
→ successive L1 diff

应在每次有效 L2 mutation 时得到：
side
price
old_size
new_size
best bid/ask before
best bid/ask after

生成：
BookFlowEvent

然后构建：
event_ofi
rolling_ofi
normalized_ofi

注意：
不要为了计算 OFI 修改 OrderBook 成 Feature Engine。
正确边界：
OrderBook
→ 描述 mutation

FeatureEngine
→ 解释 mutation

Market 层仍然只负责市场事实。
6. Rolling Window
建立统一窗口基础设施，不允许每个 feature 自己保存数组。
需要至少两种窗口：
TimeWindow
EventWindow

例如：
OFI_1s
OFI_5s
OFI_15s

trade_volume_1s
trade_volume_5s

return_1s
return_5s
return_15s
return_30s
return_60s

Window 的时间必须来自：
ReplayClock / event time

不能用：
time.time()

这样 Live 与 Replay 才能一致。
7. Returns
建立正式的价格历史：
mid(t)

然后定义：
return_h =
mid(t) / mid(t-h) - 1

第一阶段：
1s
3s
5s
15s
30s
60s
300s

这里要注意：
event-driven 数据没有保证刚好存在 t-5s 的事件。

因此必须明确：
latest observation <= target timestamp

的 lookup 规则。
不能用未来一条数据补过去。
8. Volatility
第一版只需要 realized volatility，不做预测 volatility。
例如窗口：
5s
15s
30s
60s

定义必须在 proposal / tests 固定。
避免 lob-engine 出现过的：
per-observation sigma
× seconds

这种量纲混用。
Volatility 的时间尺度必须明确以秒定义，而不是以“多少个 event”定义。
9. VAMP
不要混淆：
VWAP

和：
VAMP

本阶段 VAMP 只来自 Order Book。
明确固定一种定义并版本化。
如果当前 V3 的定义确认合理，可以保持兼容；但必须在代码和 schema 中写清公式，不能只叫 vamp。
10. DataQuality
这是 Jev 前面的正式闸门。
输出：
DataQuality

至少包括：
book_healthy
book_age_ms

trade_stream_available
trade_age_ms

history_ready
window_coverage

sequence_contiguous

feature_ready

最终：
MarketState.tradeable

不等于：
BookHealth == HEALTHY

而应类似：
book healthy
AND required features ready
AND data age valid

但这里只描述市场数据是否可以用于决策。
不包含资金、仓位、Risk。
11. Feature Schema Version
必须现在做：
feature_schema_version

因为以后 Jev 的实验必须能回答：
这个预测到底用了哪套 feature？

例如：
market-state-v1

一旦某个 feature：
- 改公式
- 改单位
- 改窗口
- 改缺失值语义
必须升级 schema。

“根本没有数据”
