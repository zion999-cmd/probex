## 0. 本阶段固定契约（供审查）

### 0.1 observer 故障隔离（`_notify_discontinuity`）

1. **先记录事实**：`discontinuity_events` 追加 reason（在任何 listener 调用之前）。
2. **逐个独立调用**：每个 listener 单独 `try`，一个失败不影响其他 listener。
3. **绝不向上抛**：listener 异常不得中断 `_reconnect` / `_recreate_listen_key` / `stop()` 的既有语义。
   只捕获 `Exception`（**不吞** `BaseException`：`KeyboardInterrupt` / `SystemExit` 照常传播）。
4. **可审计、无凭据**：失败计数 `discontinuity_listener_failure_count`（沿用现有 counter 风格）
   + `last_error = "discontinuity listener failed: <ExceptionType>"`——
   **只记录异常类型名**，不记录消息/参数/堆栈（避免把敏感内容写进 telemetry）。

### 0.2 文档状态清理（SC-6）

`context/current_state.md` / `context/handoff.md` 中「尚未提交」的表述已被后续 commit 推翻：
一律改写为当前事实（commit hash + push 状态）；保留的历史报告段落必须显式标注 **superseded**。

### 0.3 不动的东西

recovery 业务语义 / ownership / fill 分类 / ExecutionAdapter / available balance / 历史 PnL / P0001.10 均不涉及。
目标
保证 recovery invalidation 的 observer 机制本身不会破坏 private runtime 的断线恢复路径，并清除当前状态文档中的已失效提交状态。
背景
P0001.9.3.1 已正确建立：
runtime discontinuity
→ subscriber
→ recovery NOT_RECOVERED

但当前 subscriber callback 没有故障隔离，和代码注释声明的契约不一致。
架构
disconnect
   ↓
record discontinuity
   ↓
notify listener A ──throws──┐
notify listener B           │
   ↓                        │
runtime reconnect <─────────┘ 不得被破坏

设计
_notify_discontinuity() 必须满足：
1. discontinuity 事实先记录
2. 每个 listener 独立调用
3. 某 listener 失败不得阻止其他 listener
4. 不得阻止 runtime reconnect / listenKey recreate / stop
5. listener failure 必须可审计，但不得包含凭据

具体错误记录方式由实现方沿用现有 telemetry/counter 风格，不新建 logging 系统。
同时清理 current_state/handoff 中已被后续 commit 推翻的“尚未提交”表述；若保留历史报告，明确标记 superseded，不要伪装成当前状态。
边界
包含
- discontinuity listener exception isolation
- listener failure telemetry/审计
- 多 listener 故障测试
- reconnect / recreate / stop 回归测试
- context 文档状态清理
不包含
- 不改 recovery 业务语义
- 不改 ownership
- 不改 fill classification
- 不实现 ExecutionAdapter
- 不解决 available balance
- 不做历史 PnL
- 不做主网交易
- 不进入 P0001.10
