P0001.10.3：Product CLI / Agent Interface
状态：已完成
依赖：P0001.10.1 Product Read Model + API
目标
给 Probex 增加稳定 CLI，使人类、Shell、Claude Code、Pi、其他 Agent 都能通过同一产品契约访问系统。
核心关系：
Domain Owners
      ↓
Product Service
      ↓
 ┌────┼─────┐
 API  CLI    UI
      ↓
     AI

CLI 不成为新的业务 Owner。
设计重点
CLI 必须首先是“机器接口”，其次才是人类终端。
例如：
probex status
probex snapshot
probex market
probex prediction
probex strategy
probex risk
probex orders
probex portfolio
probex readiness
probex evidence

并统一支持：
probex snapshot --json
probex risk --json
probex evidence --json

这样 AI 不需要解析漂亮的 terminal 文本，直接消费稳定 JSON。
进一步可以支持：
probex evidence --decision-id xxx
probex orders --active
probex readiness --explain

这对 Agent 很重要，因为它就可以问系统：
为什么没下单？

而不是自己猜。
AI 扩展的真正关键
不是让 AI “随意调用 Python 模块”，而是：
AI
 ↓
CLI Contract
 ↓
Product Service
 ↓
Existing Owners

以后无论 Claude Code、ChatGPT Work、Hermes、MCP，甚至自写 Agent，只要会执行命令，就能接 Probex。
甚至可以自然演化成：
probex snapshot --json
probex explain decision <id> --json
probex report run <id> --json

AI 层完全不需要理解内部目录结构。
边界
第一版 CLI 只读：
status / inspect / query / report / explain

不要现在加入：
probex buy
probex sell
probex order
probex set-risk
probex set-leverage

否则 CLI 会变成绕过现有：
MakerPolicy
→ RiskGate
→ ReadinessAuthority
→ ExecutionEngine

的第二条控制路径。
以后确实可以有控制命令，但必须调用既有受控 command/service，不能直接打 Binance adapter。
我额外建议两个契约
一是稳定退出码：
0   success
2   invalid arguments
10  unavailable
11  unknown / insufficient evidence
20  blocked by policy/readiness
30  internal failure

二是 stdout/stderr 分离：
stdout = 数据
stderr = diagnostics

这样 Agent 调 CLI 时非常干净。

### 契约落地

- **稳定退出码**：`0` 成功 / `2` 参数错误（含所有不存在的写命令）/ `10` API 不可用 / `11` 证据不足（UNKNOWN）/ `20` 被 policy·readiness 阻塞（`readiness --strict`）/ `30` 内部错误；
- **stdout/stderr 分离**：stdout 只放数据（`--json` 时是稳定 JSON），诊断/错误只走 stderr（`test_stdout_is_data_and_stderr_is_diagnostics`）；
- **机器优先**：AI/Shell 直接消费 `probex <cmd> --json`，无需解析终端文本，也无需理解内部目录结构；
- **只读**：命令表内**不存在** `buy` / `sell` / `order` / `set-risk` / `set-leverage` / `cancel`（`test_no_write_commands_exist` 同时断言命令表与退出码）；
- **不成为第二控制路径**：CLI 只经 Product API 读取事实，不 import 领域模块、不触碰 Binance adapter。
