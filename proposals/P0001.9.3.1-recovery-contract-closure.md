## 0. 本阶段固定契约补充（供审查）

### 0.1 成交三分类（替换 P0001.9.3 的两分类）

| 类别 | 判定 | 处理 |
| --- | --- | --- |
| 自己的 | `orderId` 映射存在且 `clientOrderId` 严格匹配 `probex-` | 归一化为 `ExternalFill` → reconcile |
| 已验证外部 | 映射存在但 `clientOrderId` **不是**我们的 | 丢弃并计数（`foreign_fills` / `foreign_order_ids`） |
| **不可归属** | 映射**不存在**（orderId 从未出现在 openOrders ∪ allOrders 窗口内） | `unresolved_fill_order_ids` ⇒ `BLOCKED: UNRESOLVED_FILLS`（**不降级为 telemetry**） |

### 0.2 ownership 严格前缀

`OWNED_CLIENT_ORDER_ID_PREFIX = "probex-"`，且要求前缀之后**至少还有一个字符**：

`probex-s1-000001` ✓ 自有；`probexevil-1` / `probex2` / `probex` / `probex-` ✗ 外部。

### 0.3 runtime → recovery 失效接线（SC-4 / SC-5）

- `PrivateAccountRuntime.subscribe_discontinuity(listener)`：断线重连 / listenKey 重建 / `stop()`
  都会记录 `discontinuity_events` 并广播 reason（不含凭据）。
- `StartupRecovery.on_stream_discontinuity(reason)` + `StartupRecovery.bind(runtime)`：订阅即自动失效。
- 测试**不得**用 `recovery.invalidate()` 模拟接线；必须在真实断线路径上断言（SC-4）。
