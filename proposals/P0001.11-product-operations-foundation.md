状态：已完成

目标
让 Probex 从“能运行、能查看”升级为“每次运行都可识别、可追溯、可比较、可解释”。
这一阶段先吸收 Freqtrade / Hummingbot 最成熟、且不会污染交易核心的产品能力：
Config Provenance
+
Run Registry
+
Metric Contract
+
Capability Manifest
+
Unified Blockers

不是增加策略，也不是接外部交易框架。

RunSummary
API
UI
CLI
Reports

但这些仍缺少“跨运行”的产品语义。

我知道系统现在是什么状态

但还不能很好回答：
这次为什么这样运行？
用了什么配置？
跟昨天那次相比怎样？
这个指标怎么算？
AI 到底允许做什么？

### A. Metric Contract 裁决
- Sharpe：**固定时间间隔 equity return**，第一版 **1 分钟采样**，**无风险利率 = 0**，样本 **< 30 ⇒ UNKNOWN**。
- MDD：报告指标 = **run 内 equity peak-to-trough**（命名 `run_mdd`）；**不复用 durable HWM**。
  `Run MDD`（本次运行表现）与 `Risk drawdown`（trusted activation point 风控权威）**必须命名区分**。
- Profit Factor：只用**已实现交易结果**，`gross_profit / abs(gross_loss)`；**fees/funding 单列不混入**；
  **无亏损样本 ⇒ UNKNOWN（不返回 ∞）**。
- Max Exposure：同时保留 `max_confirmed_exposure` 与 `max_total_exposure`（后者含 uncertain/pending）。
- Net PnL：**不得让 reports 重新推导账户真相** —— 优先读 AccountingCore 已记录的权威结果，缺失 ⇒ UNKNOWN。

### B. Run Registry 裁决
- 四种模式全部注册（REPLAY / PAPER / TESTNET / LIVE）。
- 仓库外存储（默认 `~/.probex/runs/`，env 可覆盖）；append/index + atomic write；不必达 HWM 级 durability，但**不得半写**。
- runtime identity 创建时建 run；正常 stop 时 close；**崩溃未 close ⇒ `INCOMPLETE`（不是 UNKNOWN）**。
- run record 尽量 immutable；结束时**追加 finalization record**，不覆盖历史。
- 本阶段**只支持单 writer**；不做 retention 自动删除；run registry 是**产品数据**，与 governance 完全分离。

### C. Config Provenance 裁决
- 只记录**非敏感** resolved values；secret 只记录引用名（如 `env:BINANCE_API_KEY`），**永不保存 secret value**。
- fingerprint = canonical JSON + schema version + 非敏感 resolved values + secret reference names。
- source 分类固定：`FILE` / `ENV` / `CLI` / `CONSTRUCTOR`；优先级 `CLI > ENV > FILE > CONSTRUCTOR`，
  但**业务值仍不得有隐式默认**。产品层**不读取** `~/.probex/*.env` 的 secret 值，只接收解析后的 provenance metadata。

### D. Unified Blockers 裁决
- **不人为排序成单一最高优先级**（避免掩盖并发问题）；每条至少带 `owner` / `reason_code` / `severity` / `message` / `source_ref`。
- severity 只有 `BLOCKING` / `DEGRADED` / `INFO`；去重键 = `owner + reason_code + source_ref`；
  UI 可排序但**不得丢弃低优先级 blocker**。

### E. Capability Manifest 裁决
- 必须**尽量从路由/CLI 注册表生成**，避免手写漂移；至少含 `api.read` / `api.write` / `cli.commands` / `exit_codes` / `schema_version`。
- 加测试固定 `write actions = unavailable_by_design`；未来真加写能力时测试必须显式改动。

### F. Run Compare / Schema 裁决
- 比较按同名 metric 对齐；**一边 UNKNOWN ⇒ delta = UNKNOWN**；两边 known 才允许 delta。
- schema version 由 `"1"` 升级为 `"2"`（新增产品字段/端点）。
- CLI 新增 `runs` / `run show` / `run compare` / `metrics` / `capabilities` / `blockers`；**原退出码 0/2/10/11/20/30 不改**。

### 1. F-12 Network / Auth Posture（CLOSED）

- **姿态固定**：默认 `bind = 127.0.0.1`（loopback，不强制认证）；非 loopback **必须** `--allow-non-loopback` 显式 opt-in，
  且**必须**配置 bearer token 的 secret 引用；缺任一 ⇒ `AssemblyError` 拒绝启动（不做"警告后继续"）。
- **secret 路径唯一**：token 只从 `--auth-token-ref env:NAME`（或 `PROBEX_AUTH_TOKEN_REF`）解析；值**不进入**
  ConfigSnapshot / provenance 明文（provenance 只记录 `env:NAME` 引用）、Product snapshot、logs、action audit、异常消息；
  解析出的值登记到 redactor（任何日志/异常都会遮蔽）。
- **非 loopback API**：所有 `/api/v1/*` 一律需要 `Authorization: Bearer <token>`（常量时间比较）——包括 actions / execution /
  replay，**没有匿名旁路**；缺/错 ⇒ 401（`WWW-Authenticate: Bearer`），失败只记 `AUTH_TOKEN_MISSING` / `AUTH_TOKEN_INVALID`
  （不记录 header / token / 长度）。loopback 行为不变（UI/CLI 不被无意义打断）。
- `GET /health/live` 免认证（纯进程 liveness，不含事实）。
- **不包含**：用户系统 / RBAC / OAuth / session login / refresh token / 多租户。

### 2. F-15 Structured Logging（CLOSED）

- 新增 `runtime/observability.py`（stdlib logging only）：单行 JSON，稳定字段
  `ts / level / event / component` + 可选 `runtime_id / run_id / mode / reason_code`；未配置前挂 `NullHandler`
  （不向 stderr 泄漏半结构化输出）；`configure_logging` 支持 stderr / 文件 sink（`retention.log_max_bytes` +
  `retention.log_backup_count` ⇒ 有界轮转；未配置 size ⇒ 姿态如实 UNBOUNDED）。
- **覆盖事件**：startup / shutdown / runtime_start / runtime_stop / runtime_failure / run_start / run_finalize /
  run_failure / action_invoke / action_result / action_refusal / confirmation_required / confirmation_invalid /
  reconciliation_requested / external_fact_source_failure / api_5xx / http_request_error / unexpected_exception /
  auth_failure / retention_prune。
- **secret 纪律**：敏感字段名一律 redact；已注册 secret 值在任意字符串中替换；`signature=` query 与 `bearer <token>` 同样 redact；
  异常只记 `exception_type` + sanitized message。
- 真实 REPLAY 启动日志（`PROBEX_LOG_FILE`）：`run_start → runtime_start → startup → … → run_finalize → runtime_stop → shutdown`。

### 3. F-15 Retention / Growth Policy（CLOSED）

- 新增 `storage/retention.py`：`RetentionPolicy`（`run_max_runs` / `run_max_age_ms` / `event_store_max_bytes` /
  `log_max_bytes` / `log_backup_count`）——**全 None ⇒ UNBOUNDED**，绝不隐式删除；`run_max_runs=0` 直接拒绝。
- `prune_finished_runs(registry, policy, now_ms)`：只处理**有 finalize 事件**的 run（RUNNING / 崩溃残留一律保留，不掩盖崩溃）；
  删除 record 文件并**原子压缩索引**（保留其余事件顺序）；**active run 永不删除**（`remove_runs` 内部再次剔除，双保险）。
- event store **永不自动删除/轮转**（active replay source；archival 不在范围内）；action audit 与 latency 采样天然有界（有容量）。
- 可观察：`runtime.run_retention()` 记录 `retention_prune` 日志（`RETENTION_PRUNED` / `RETENTION_NOOP`），
  `System → Ops → Retention` 展示 bounded/unbounded、当前 count/size、active policy、last prune。
- `/api/v1/runs` 分页契约不变；retention 只影响 durable 存量。

### 4. Process Liveness / Health Split（CLOSED）

- `runtime/ops.py`：四层健康**互不替代** —— `PROCESS_LIVE`（只回答"进程活着"，不依赖交易所/行情/provider）、
  `RUNTIME_RUNNING`（既有 `RuntimeStatusTracker`）、`TRADE_READINESS`（既有 readiness gate，可 fail-closed）、
  `EXECUTION_HEALTH`（P0001.13）。
- `GET /health/live`（免认证，纯 liveness）；`GET /api/v1/ops`（network/auth/logging/retention + 四层健康）；
  `snapshot.ops` 供 UI/CLI/Assistant 共用。

### 5. Crash / Restart 最小验证（CLOSED）

- graceful stop ⇒ run `COMPLETED` + active marker 清除（真实 SIGTERM 验证）。
- crash-like（SIGKILL）⇒ 无 finalize ⇒ 读侧 `INCOMPLETE`（**不伪造 COMPLETED**）；stale/dead marker 不被当作 `RUNNING`。
- **PID 复用防护**：`active_run_id` 现在要求 marker 记录的 `process_started_at_ms` 与当前该 pid 的启动时刻一致；
  `os.kill(pid,0)` 对僵尸进程会成功 ⇒ 新增 `process_is_alive`（Linux `/proc` 状态、macOS `ps -o stat=`，僵尸视为已死）。
  仍然**不是** TTL 判断。
- restart ⇒ run history 仍在（崩溃 run 显示 `INCOMPLETE`）、HWM durable state 仍在、config provenance 可重新读取。
