P0001.13：Execution Safety & Operations Surface
状态：已提议
日期：2026-09-29
依赖：P0001.12
目标
一边补执行层产品化缺口，一边把这些安全边界完整映射到 UI / API / CLI。
核心不是“加几个 limiter”，而是让用户能明确知道：
现在为什么能下单？
为什么不能下单？
还剩多少执行额度？
交易所限制是什么？
最近执行链路延迟如何？
当前是健康、降级还是阻塞？

架构
Venue Facts
   │
   ├─ rate limits
   ├─ order limits
   ├─ symbol filters
   └─ timing facts
   │
   ▼
Execution Safety Projection
   │
   ├─ RateLimitGovernor
   ├─ VenueLimitState
   ├─ LatencyBudget
   └─ ExecutionHealth
   │
   ▼
Product Service
   │
   ├─ API
   ├─ UI
   └─ CLI

设计
1. Rate-limit / Order-rate Governance
加一个 Probex 自己拥有的 limiter，不直接搬 ccxt / Hummingbot。
输出事实：
request_budget
order_budget
used
remaining
reset_at
source
known/unknown

约束：
- 不改变 UNKNOWN submit 语义
- 不因为限流自动 retry submit
- 不绕过 ExecutionEngine
- cancel/de-risking 仍按现有安全语义处理
2. Venue Limit Facts
把交易所已有事实正式产品化，例如：
tick_size
step_size
min_qty
max_qty
min_notional
max_orders
request_weight limits
order count limits

这些来自交易所事实源，不允许 UI 自己推导。
3. Execution Latency Budget
不是做 benchmark 炫技，而是定义几个稳定阶段：
decision_to_submit
submit_to_ack
cancel_to_ack
event_receive_lag
reconciliation_duration

输出：
p50
p95
max
sample_count
budget
status

不使用绝对硬件性能作为“业务正确性”，但可以作为运行健康信号。
4. Execution Health
形成统一：
HEALTHY
DEGRADED
BLOCKED
UNKNOWN

来源至少包括：
rate-limit state
private latency
market health
reconciliation
uncertain exposure
venue facts freshness

不替代 Readiness，只做产品投影。
UI 必须同步做
这一阶段 UI 不是附属，而是交付的一半。

边界
包含
- Probex-owned rate-limit governance
- venue limit facts
- latency metrics
- execution health projection
- UI execution operations surface
- API / CLI 查询
- blocker integration
- timeline/health visualization
- contract tests
不包含
- 不接 ccxt limiter
- 不接 Hummingbot connector limiter
- 不改变订单状态机
- 不改变 RiskGate
- 不改变 ReadinessAuthority
- 不改变 UNKNOWN submit 语义
- 不自动重试 submit
- 不增加人工下单
- 不做 multi-venue
- 不做策略功能
- 不做算法调优
- 不做 WebSocket execution control
- 不让 UI 成为控制面
成功标准
1. 用户能在 UI 看到当前执行是否健康。
2. rate limit 状态来自真实 venue facts。
3. 接近/耗尽限额时状态明确变化。
4. 不会因 limiter 触发自动 submit retry。
5. venue limits 与 normalization 使用同一事实源。
6. latency 有稳定定义和采样数。
7. UNKNOWN / unavailable 显式，不显示成 0。
8. blocker 能指出执行为什么受限。
9. API / CLI / UI 使用同一 projection。
10. 不引入第二条交易写路径。
11. 不改变现有订单、风控、readiness 语义。
12. 全量测试不回归。
